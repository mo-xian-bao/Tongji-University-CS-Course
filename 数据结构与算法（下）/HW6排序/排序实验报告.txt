排序算法实验报告

一、数据结构与相关背景

排序算法是计算机科学中最基本也是最重要的算法之一，它们被广泛应用于数据处理、搜索优化和计算机图形学等领域。本报告将介绍以下几类排序算法：

1. 插入排序类

插入排序类算法的基本思想是将一个新元素插入到已排好序的序列中，形成一个新的有序序列。

1.1 直接插入排序

基本思路：从第二个元素开始，将其与前面已排序的元素比较，找到合适位置插入。

实现方式：通过不断将元素与前面的元素比较并交换位置，直到找到正确的位置。

时间复杂度：
- 最好情况：O(n)（数组已经有序）
- 最坏情况：O(n?)（数组逆序）
- 平均情况：O(n?)

空间复杂度：O(1)，原地排序算法

稳定性：稳定。在插入过程中，相等元素的相对位置不会改变。

1.2 折半插入排序

基本思路：利用二分查找来加速查找插入位置的过程。

实现方式：对于每个新元素，使用二分查找在已排序部分找到插入位置，然后移动元素并插入。

时间复杂度：
- 查找操作：O(log n)
- 移动操作：O(n)
- 总体时间复杂度：O(n?)（虽然查找加速了，但移动操作仍需O(n)）

空间复杂度：O(1)

稳定性：稳定。二分查找只影响查找插入位置的效率，不影响元素的相对顺序。

1.3 表插入排序

基本思路：使用链表结构进行插入排序，避免数组移动元素的开销。

实现方式：维护一个有序链表，每次将新元素插入到链表的适当位置。

时间复杂度：O(n?)
空间复杂度：O(n)（需要额外的链表结构）

稳定性：稳定。可以保证相等元素的相对位置不变。

1.4 希尔排序

基本思路：将序列分成若干子序列，对每个子序列进行直接插入排序，逐步缩小增量直到为1。

实现方式：按照增量序列（如Knuth序列）将数组分组，对每组进行插入排序，然后减小增量再排序。

时间复杂度：取决于增量序列，一般为O(n^1.3)到O(n?)之间
空间复杂度：O(1)

稳定性：不稳定。由于希尔排序是跳跃式的插入排序，相同元素可能会被分到不同的子序列中，导致相对位置改变。

2. 交换排序类

交换排序类算法的基本思想是通过交换元素位置来达到排序的目的。

2.1 起泡排序（冒泡排序）

基本思路：重复遍历序列，比较相邻元素并交换不符合顺序的元素对。

实现方式：每次遍历将最大（或最小）元素"冒泡"到序列的一端。

时间复杂度：
- 最好情况：O(n)（使用标志位优化且数组已有序）
- 最坏情况：O(n?)
- 平均情况：O(n?)

空间复杂度：O(1)

稳定性：稳定。只有当相邻元素大小关系不满足要求时才交换，相等元素不会交换，因此保持原有顺序。

2.2 快速排序

基本思路：选择一个基准元素，将序列分为两部分，一部分小于基准，一部分大于基准，然后递归排序两个子序列。

实现方式：通过分区（partition）操作将数组分为两部分，然后递归处理。

时间复杂度：
- 最好情况：O(n log n)
- 最坏情况：O(n?)（当数组已排序时）
- 平均情况：O(n log n)

空间复杂度：O(log n)（递归调用栈）

稳定性：不稳定。在分区过程中，元素的相对位置可能发生改变，特别是与基准元素相等的元素。

3. 选择排序类

选择排序类算法的基本思想是每次从未排序部分选择最小（或最大）的元素放到已排序部分的末尾。

3.1 简单选择排序

基本思路：每次从未排序部分找出最小元素，放到已排序部分的末尾。

实现方式：通过n-1次遍历，每次找出最小元素并交换到前面。

时间复杂度：O(n?)（无论输入如何）
空间复杂度：O(1)

稳定性：不稳定。在交换过程中，相等元素的相对位置可能发生改变。例如，当最小元素与前面相等的元素交换位置时。

3.2 树形选择排序（锦标赛排序）

基本思路：使用完全二叉树结构进行比较，找出最小元素。

实现方式：构建一个胜者树，每次选出最小值后重新调整树结构。

时间复杂度：O(n log n)
空间复杂度：O(n)

稳定性：稳定。可以通过适当的实现保证相等元素的相对位置不变。

3.3 堆排序

基本思路：利用堆数据结构（通常是最大堆）进行排序。

实现方式：先构建最大堆，然后每次取出堆顶元素（最大值）放到数组末尾，并重新调整堆。

时间复杂度：O(n log n)
空间复杂度：O(1)

稳定性：不稳定。在堆调整过程中，相等元素的相对位置可能发生改变。

4. 归并排序

基本思路：将序列分成两部分，分别排序后再合并。

实现方式：递归地将数组分为两半，排序后再合并两个有序数组。

时间复杂度：O(n log n)（各种情况下都是）
空间复杂度：O(n)（需要额外空间来合并数组）

稳定性：稳定。在合并过程中，可以保证相等元素的相对位置不变。当两个元素相等时，可以先选择前一个子数组中的元素，保证稳定性。

5. 基数排序

基本思路：按照元素的位数进行多次分配和收集。

实现方式：从最低位（或最高位）开始，对每一位进行桶排序，然后合并。

时间复杂度：O(d(n+r))，其中d是位数，r是基数（如十进制r=10）
空间复杂度：O(n+r)

稳定性：稳定。在每一轮的分配和收集过程中，相等元素的相对位置不会改变。

二、实验内容
1.求逆序对
1.1 问题描述
对于一个长度为N的整数序列A，满足i < j 且 Ai > Aj的数对(i,j)称为整数序列A的一个逆序。
请求出整数序列A的所有逆序对个数
1.2 基本要求
输入
输入包含多组测试数据，每组测试数据有两行
第一行为整数N(1 <= N <= 20000)，当输入0时结束
第二行为N个整数，表示长为N的整数序列
输出
每组数据对应一行，输出逆序对的个数
1.3 数据结构设计
本算法主要使用了 `std::vector<int>` 来存储输入的整数序列。`vector` 是一种动态数组，能够方便地存储和访问序列中的元素。此外，在归并排序过程中，还使用了一个与原序列等大的辅助 `vector<int> temp`，用于在合并子序列时临时存放排好序的元素，以避免在原数组上直接操作造成的干扰，并保证合并操作的正确性。选择 `vector` 是因为它提供了高效的随机访问能力（在归并排序的合并阶段需要），并且能够动态调整大小（虽然本例中大小固定）。
1.4 功能说明（函数，类）
    *   **`long long merge(vector<int>& arr, vector<int>& temp, int left, int mid, int right)`**:
        *   **功能**: 该函数是归并排序的核心合并步骤。它负责将两个已经排序好的子序列（`arr[left...mid]` 和 `arr[mid+1...right]`）合并成一个有序序列，并存放在临时数组 `temp` 中。
        *   **关键作用**: 在合并过程中，当发现左子序列的元素 `arr[i]` 大于右子序列的元素 `arr[j]` 时（即 `arr[i] > arr[j]`），表明找到了逆序对。由于左子序列 `arr[left...mid]` 自身已经有序，此时 `arr[i]` 到 `arr[mid]` 之间的所有元素都比 `arr[j]` 大，因此可以一次性计算出 `mid - i + 1` 个逆序对，并将这个数量累加到逆序对总数 `inversions` 中。这是本算法高效计算逆序对的关键。
        *   **返回值**: 返回本次合并过程中发现的跨越两个子序列的逆序对数量。

    *   **`long long mergeSort(vector<int>& arr, vector<int>& temp, int left, int right)`**:
        *   **功能**: 这是归并排序的递归实现函数。它采用分治策略，将序列不断二分，直到子序列长度为1（天然有序）。
        *   **关键作用**: 递归地调用自身处理左右子序列，并累加左右子序列内部的逆序对数量。然后调用 `merge` 函数合并两个已排序的子序列，并累加合并过程中产生的跨子序列的逆序对数量。
        *   **返回值**: 返回指定范围 `[left, right]` 内的总逆序对数量。

    *   **`long long countInversions(vector<int>& arr)`**:
        *   **功能**: 这是计算逆序对的入口函数。
        *   **关键作用**: 初始化临时数组 `temp`，并调用 `mergeSort` 启动整个归并排序和逆序对统计过程。
        *   **返回值**: 返回整个序列 `arr` 的逆序对总数。

    *   **`int main()`**:
        *   **功能**: 程序主函数，负责处理输入输出逻辑。
        *   **关键作用**: 读取多组测试数据，包括序列长度 `N` 和序列本身。当 `N` 为0时结束程序。对每组数据调用 `countInversions` 函数计算逆序对，并输出结果。
1.5 调试分析（遇到的问题和解决方法）
在解决求逆序对数问题时，最初的直观想法是使用双重循环进行暴力枚举。即遍历所有可能的数对 `(i, j)`，其中 `i < j`，然后判断是否满足 `A[i] > A[j]`。如果满足，则逆序对计数加一。

```cpp
// 暴力枚举思路（未实际使用）
long long count_bruteforce(vector<int>& arr) {
    long long count = 0;
    int n = arr.size();
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            if (arr[i] > arr[j]) {
                count++;
            }
        }
    }
    return count;
}
```

**遇到的问题**: 这种暴力枚举方法的时间复杂度为 O(N?)。当 N 达到题目要求的最大值 20000 时，N? 约为 4 * 10?，计算量过大，会导致程序运行超时（Time Limit Exceeded, TLE），无法通过所有测试用例。

**解决方法**: 经过分析和学习，发现归并排序算法可以在排序的同时高效地统计逆序对。在归并排序的合并（merge）阶段，当我们需要将右侧子数组的元素 `arr[j]` 放入临时数组，且此时左侧子数组的指针 `i` 指向的元素 `arr[i]` 大于 `arr[j]` 时，就意味着左侧子数组中从 `arr[i]` 到 `arr[mid]` 的所有元素都与 `arr[j]` 构成了逆序对。利用这一特性，可以在 O(N log N) 的时间复杂度内完成排序和逆序对统计。因此，改用基于归并排序的方法来实现，最终代码如 `求逆序对数.cpp` 所示，成功解决了时间复杂度过高的问题。
1.6 总结和体会
通过本次实验，我深刻理解了求逆序对数问题的不同解法及其效率差异。暴力枚举法虽然直观简单，但在数据规模较大时效率低下，无法满足性能要求。而基于归并排序的算法则巧妙地利用了排序过程中的比较信息来统计逆序对，将时间复杂度优化到了 O(N log N)，大大提高了算法的效率，能够处理更大规模的数据。

这次实验让我体会到：
1.  算法设计中时间复杂度的重要性，选择合适的算法对程序性能至关重要。
2.  归并排序不仅是一种高效的排序算法，其分治思想和合并过程还可以被巧妙地应用于解决其他问题，如计算逆序对。
3.  理解算法的内在原理有助于我们发现其潜在的应用价值。认识到 `merge` 操作中比较大小的步骤天然地揭示了逆序对的存在，是解决此问题的关键。
4.  编写代码不仅要实现功能，还要考虑效率和资源消耗，针对具体问题选择最优的数据结构和算法是提升程序质量的有效途径。

2.最大数
2.1 问题描述
给定一组非负整数 nums，重新排列每个数的顺序（每个数不可拆分）使之组成一个最大的整数。
注意：输出结果可能非常大，所以你需要返回一个字符串而不是整数。
2.2 基本要求
输入描述
输入包含两行 第一行包含一个整数n，表示组数nums的长度

第二行包含n个整数nums[i]

对于100%的数据，1<=nums.size()<=100，0<=nums[i]<=10^9；
输出描述
输出包含一行，为重新排列后得到的数字

2.3数据结构设计
该算法主要使用了 `std::vector<int>` 来存储输入的非负整数。为了实现自定义排序规则，算法将这些整数转换成 `std::string` 类型，并存储在 `std::vector<string>` 中。最终结果也以 `std::string` 的形式返回，以处理可能非常大的整数。
2.4功能说明
*   **`class Solution`**: 封装了解决问题的逻辑。
    *   **`static bool compare(const string& a, const string& b)`**:
        *   **功能**: 这是一个自定义的比较函数，用于确定两个数字字符串 `a` 和 `b` 的拼接顺序。
        *   **关键作用**: 定义了排序的核心规则：如果 `a + b` (字符串拼接) 大于 `b + a`，则认为 `a` 应该排在 `b` 前面。这个规则确保了能组成最大整数的排列顺序。例如，比较 "3" 和 "30"，因为 "330" > "303"，所以 "3" 排在 "30" 前面。
    *   **`void BubbleSort(vector<string>& strs)`**:
        *   **功能**: 使用冒泡排序算法，根据 `compare` 函数定义的规则对字符串向量 `strs` 进行排序。
        *   **关键作用**: 将数字字符串按照能组成最大整数的顺序排列好。虽然标准库提供了更高效的 `std::sort`，这里选择自定义冒泡排序是为了演示排序过程。
    *   **`string largestNumber(vector<int>& nums)`**:
        *   **功能**: 主函数，接收整数向量 `nums`，将其转换为字符串向量，调用排序函数进行排序，最后将排序后的字符串拼接成最终的最大整数字符串。
        *   **关键作用**: 协调整个流程，处理整数到字符串的转换、调用排序、处理特殊情况（如全零输入）并返回结果。
2.5调试分析
**遇到的问题**:
最初的想法可能是直接对数字进行某种数值上的比较，但这很快会发现行不通。例如，对于 `[3, 30, 34, 5, 9]`，简单的数值排序（3, 5, 9, 30, 34）或者逆序（34, 30, 9, 5, 3）都无法直接得到最大组合 "9534330"。问题的关键在于如何确定两个数字 `a` 和 `b` 的先后顺序才能使得组成的整数最大。

**解决方法**:
通过分析发现，决定两个数字 `a` 和 `b` 先后顺序的正确方法是比较两种拼接方式 `a + b` 和 `b + a` 的字典序大小。如果 `a + b > b + a`，则 `a` 应该排在 `b` 前面。基于这个发现，定义了一个自定义比较函数 `compare`。然后，将所有输入数字转换为字符串，并使用这个自定义比较函数对字符串进行排序（代码中使用了冒泡排序，也可以使用 `std::sort`）。排序后，将字符串按顺序拼接起来即可得到最大的整数。还需要处理一个特殊情况：如果排序后的第一个字符串是 "0"（意味着所有输入数字都是0），则结果应为 "0"，而不是多个 "0" 的拼接。
2.6总结与体会部分
本次实验解决了一个有趣的排序问题。核心在于理解并实现了一个非传统的比较规则，即通过比较字符串拼接后的字典序来决定原始数字的排列顺序。这让我认识到：
1.  排序问题的关键有时并非数值大小本身，而是根据特定目标定义的相对顺序。
2.  将数字转换为字符串处理是解决这类问题的有效技巧，可以方便地实现拼接比较。
3.  自定义比较函数是 C++ `std::sort` 或自行实现排序算法（如本例中的冒泡排序）的强大工具，能够灵活适应各种排序需求。
4.  需要注意处理边界情况和特殊输入，例如输入全为零的情况。

4.序列
4.1 问题描述
给定m个数字序列，每个序列包含n个非负整数。我们从每一个序列中选取一个数字组成一个新的序列，显然一共可以构造出n^m个新序列。接下来我们对每一个新的序列中的数字进行求和，一共会得到n^m个和，请找出最小的n个和
4.2 基本要求
输入格式:
输入的第一行是一个整数T，表示测试用例的数量，接下来是T个测试用例的输入
每个测试用例输入的第一行是两个个正整数m（0 < m <= 100）和n(0 < n <= 2000)，
然后有m行，每行有n个数，数字之间用空格分开，表示这m个序列
序列中的数字不会大于10000
输出格式：
对每组测试用例，输出一行用空格隔开的数，表示最小的n个和 

4.3数据结构设计
该算法使用了 C 风格的整型数组 `sum[MAXN]` 和 `new_line[MAXN]` 来存储数据，其中 `MAXN` 是一个预定义的常量。`sum` 数组用于存储和更新当前已合并序列的前 n 小和。`new_line` 数组用于临时存储新读入的一行序列。核心部分使用了 `std::priority_queue<int>`（默认是大顶堆）来高效地维护和筛选当前组合出的 n 个最小的和。
4.4功能说明
*   **`void quick_sort(int* arr, int left, int right)`**:
    *   **功能**: 实现了标准的快速排序算法，用于对输入的每一行序列以及第一行序列（初始的 `sum` 数组）进行升序排序。
    *   **关键作用**: 确保每一行序列内部有序，这是后续 `update_sum` 函数能够正确工作的基础，因为它依赖于输入序列的有序性来优化合并过程。
*   **`void update_sum(int* sum, int* new_line, int n)`**:
    *   **功能**: 这是算法的核心。它接收当前的前 n 小和数组 `sum` 和一个新排序好的序列 `new_line`，计算出将 `new_line` 合并进来之后新的前 n 小和，并更新 `sum` 数组。
    *   **关键作用**: 通过两层循环遍历 `sum` 数组和 `new_line` 数组的所有元素对的和。利用 `std::priority_queue<int>`（大顶堆）来维护当前找到的 n 个最小的和。对于每个新计算出的和 `new_sum`，如果堆的大小小于 n，直接将其推入堆；如果堆已满，则仅当 `new_sum` 小于堆顶元素（当前最大的n个和中的最大值）时，才弹出堆顶元素并将 `new_sum` 推入。利用了输入数组已排序的特性进行了剪枝：如果 `sum[i] + new_line[j]` 已经大于等于堆顶元素，则对于固定的 `j`，后续的 `sum[i]` （因为`sum`有序）只会更大，无需继续比较，直接 `break` 内层循环。最后，将堆中的 n 个元素（即新的前 n 小和）按降序（因为是大顶堆）取出并反向存入 `sum` 数组，使其保持升序。
*   **`int main()`**:
    *   **功能**: 处理输入输出，协调调用排序和更新函数。
    *   **关键作用**: 读取测试用例数量 T，对于每个测试用例，读取 m 和 n，读取并排序第一行序列存入 `sum`，然后循环读取后续 m-1 行，每读一行就排序并调用 `update_sum` 更新 `sum` 数组。最后输出 `sum` 数组中的 n 个最小和。
4.5调试分析
**遇到的问题**:
问题的本质是求解 m 个有序序列各取一个元素组成的 n^m 个和中最小的 n 个。
1.  **暴力枚举不可行**: 最直接的想法是枚举所有 n^m 种组合，计算它们的和，然后排序取前 n 个。但当 n 和 m 较大时，n^m 会变得极其巨大，导致时间和空间复杂度都无法接受。
2.  **内存限制**: 即使不枚举所有组合，如果尝试存储中间过程产生的大量候选和，也可能超出内存限制。

**解决方法**:
代码采用了一种类似于逐步合并（或者说 k 路归并思想的变种）的方法，并结合优先队列（大顶堆）进行优化。
1.  **逐行合并**: 先将第一行排序作为初始的 n 个最小和。然后逐行读入新的序列，排序后，将其与当前已有的 n 个最小和进行"合并"，生成新的 n 个最小和。
2.  **优先队列（大顶堆）优化合并**: 在 `update_sum` 函数中，并不需要计算出 n * n 个所有的和再排序。而是使用一个大小限制为 n 的大顶堆。遍历所有可能的和 `sum[i] + new_line[j]`，动态维护堆中始终是当前遇到的最小的 n 个和。利用输入数组已排序的特性进行剪枝，可以提前结束内层循环，减少不必要的计算。
3.  **空间优化**: 这种方法只需要存储当前行的序列 (`new_line`) 和当前的前 n 小和 (`sum`)，以及一个大小为 n 的优先队列，空间复杂度主要由 O(N) 决定（如果 N > M），避免了存储大量中间状态。
4.6总结与体会部分
本次实验解决的是一个典型的"Top K"问题变种，即从大量可能的组合和中找出最小的 K 个（这里 K=n）。通过这个实验，我学到了：
1.  对于组合数量巨大的问题，暴力枚举通常不可行，需要寻找更高效的算法。
2.  优先队列（堆）是解决 Top K 问题的有力武器，可以高效地维护当前最优的一组解。
3.  分治和逐步合并的思想可以用来分解复杂问题。本题通过逐行处理，将 m 个序列的问题分解为 m-1 次"合并两个结果集"的过程。
4.  利用数据的有序性进行剪枝是常见的优化手段，可以显著减少计算量。
5.  需要关注算法的空间复杂度，选择合适的策略避免内存溢出，例如本题没有存储所有中间和，而是动态更新。

5.三数之和
5.1 问题描述
给你一个整数数组 nums ，判断是否存在三元组 [nums[i], nums[j], nums[k]] 满足 i != j、i != k 且 j != k ，同时还满足 nums[i] + nums[j] + nums[k] == 0 。请你返回所有和为 0 且不重复的三元组，每个三元组占一行。

5.2 基本要求
输入描述
2行
第1行一个整数，表示数组元素个数；
第2行输入一组整数，中间以空格分隔。
输出描述
输出所有和为0的三元组，每个三元组一行，中间以空格分隔。
对于每一个三元组，你需要按从小到大的顺序依次返回三个元素；
对于所有三元组，你需要按三元组中最小元素从小到大的顺序依次打印每一组三元组。

注意：答案中不可以包含重复的三元组。
5.3数据结构设计
算法主要使用了 `std::vector<int>` 来存储输入的整数数组 `nums`。结果存储在一个 `std::vector<vector<int>>` 类型的变量 `res` 中，其中每个内部的 `vector<int>` 代表一个满足条件的三元组。
5.4功能说明
*   **`int Partition(vector<int>& nums, int l, int r)`**: 标准的快速排序分区函数（Lomuto 分区方案的变种），选择第一个元素作为基准，将数组分为小于等于基准和大于等于基准两部分。返回基准元素最终的位置。
*   **`void QuickSort(vector<int>& nums, int left, int right)`**: 递归实现的快速排序函数，调用 `Partition` 对数组进行排序。
*   **`vector<vector<int>> threeSum(vector<int>& nums)`**:
    *   **功能**: 核心函数，找出数组 `nums` 中所有和为 0 且不重复的三元组。
    *   **关键作用**:
        1.  **排序**: 首先调用 `QuickSort` 对输入数组 `nums` 进行升序排序。排序是后续使用双指针法和高效去重的关键。
        2.  **固定第一个数**: 遍历排序后的数组，用 `nums[i]` 作为可能的三元组的第一个元素。
        3.  **剪枝与去重 (i)**: 如果 `nums[i] > 0`，由于数组已排序，后面的数都大于等于 `nums[i]`，不可能再有三数之和为 0 的情况，直接 `break`。如果 `i > 0` 且 `nums[i] == nums[i-1]`，说明这个 `nums[i]` 作为第一个数的情况已经被处理过了，`continue` 跳过以避免重复计算。
        4.  **双指针**: 对于每个固定的 `nums[i]`，使用左右指针 `left = i + 1` 和 `right = nums.size() - 1` 在数组剩余部分 `[i+1, n-1]` 中查找满足 `nums[left] + nums[right] == -nums[i]` 的两个数。
        5.  **移动指针**: 根据 `sum = nums[i] + nums[left] + nums[right]` 的值来移动指针：若 `sum == 0`，找到一个解；若 `sum < 0`，说明和太小，需要增大，将 `left` 右移；若 `sum > 0`，说明和太大，需要减小，将 `right` 左移。
        6.  **去重 (left, right)**: 当找到一个解 `sum == 0` 时，将 `{nums[i], nums[left], nums[right]}` 加入结果集 `res`。为了避免包含重复的三元组（由于数组中可能有重复元素），需要移动 `left` 和 `right` 指针，并跳过所有与刚找到的解中 `nums[left]` 和 `nums[right]` 相等的后续元素。
*   **`int main()`**: 负责读取输入数据，调用 `threeSum` 函数，并按要求格式输出结果。
5.5调试分析
**遇到的问题**:
1.  **暴力枚举 O(N?)**: 最简单的想法是使用三重循环枚举所有可能的三元组 `(i, j, k)`，判断它们的和是否为 0。但时间复杂度为 O(N?)，对于 N 较大的情况会超时。
2.  **结果包含重复三元组**: 即便找到了和为 0 的三元组，如何确保最终结果中不包含重复的三元组（例如，对于输入 `[-1, 0, 1, 2, -1, -4]`，`[-1, 0, 1]` 可能因为不同的 `-1` 而被找到两次）？
3.  **按要求排序输出**: 题目要求每个三元组内部按升序排列，所有三元组按第一个元素升序排列。

**解决方法**:
1.  **排序 + 双指针 O(N?)**: 核心优化是将时间复杂度降至 O(N?)。首先对数组进行排序（O(N log N)）。然后遍历数组，固定第一个元素 `nums[i]` (O(N))。对于数组的剩余部分，使用双指针 `left` 和 `right` 从两端向中间扫描 (O(N))，查找和为 `-nums[i]` 的两个元素。总时间复杂度为 O(N log N + N?) ≈ O(N?)。
2.  **去重策略**:
    *   **固定第一个数去重**: 在遍历 `i` 时，如果 `nums[i]` 与前一个元素 `nums[i-1]` 相同，则跳过当前循环，因为以 `nums[i-1]` 开头的所有组合已经被找过了。
    *   **找到解后去重**: 当双指针找到一个解 `(nums[i], nums[left], nums[right])` 时，在移动 `left` 和 `right` 指针之前，要持续移动它们，跳过所有与 `nums[left]` 和 `nums[right]` 重复的元素，以确保不会因为数组中的重复值而产生重复的三元组结果。
3.  **排序输出**: 由于我们首先对整个数组进行了排序，并且在将三元组加入结果集时是按照 `(nums[i], nums[left], nums[right])` 的顺序（这天然是升序的，因为 `i < left < right` 且数组已排序），所以结果自然满足了题目对输出顺序的要求。
5.6总结与体会部分
本次实验解决了一个经典的问题——三数之和。通过这个过程，我学到了：
1.  **排序的重要性**: 排序是许多数组问题的预处理步骤，它可以极大地简化后续操作，例如使用双指针和去重。
2.  **双指针技巧**: 双指针是在有序数组（或部分有序结构）中查找满足特定条件的元素对或三元组的常用且高效的技术。
3.  **去重的逻辑**: 在处理包含重复元素的输入时，去重是一个必须仔细考虑的问题。本题中通过在固定第一个数和找到解后两个环节进行判断和指针移动，有效地避免了结果重复。
4.  **算法优化思路**: 从 O(N?) 的暴力解法优化到 O(N?) 的排序加双指针解法，体现了算法设计中降低复杂度的重要性。
5.  理解问题约束和要求，例如输出格式、不允许重复等，对于设计正确的算法同样关键。

三、实验总结
本次系列实验围绕排序及其相关应用展开，涵盖了从基础排序算法性能比较到利用排序思想解决特定问题的多个方面。通过亲手实现和测试不同的算法，我对数据结构与算法的设计、选择、优化及其对程序性能的深刻影响有了更全面的认识。

具体而言，各个实验带来的主要感悟和学习收获如下：

1.  **求逆序对**：这个实验清晰地展示了算法选择对效率的巨大影响。暴力枚举法虽然直观，但 O(N?) 的复杂度使其在稍大数据规模下就不可行。而归并排序在 O(N log N) 时间内不仅完成了排序，还巧妙地利用合并过程统计了逆序对，体现了"寓寄算于排序"的思想。这让我认识到，深入理解经典算法的内在过程，可以帮助我们发现解决其他相关问题的高效途径。

2.  **最大数**：此实验的核心在于理解排序的本质是建立元素间的"序关系"。这个"序"不一定是数值大小，而是由问题目标决定的。通过定义 a+b > b+a 这样的自定义比较规则，并将数字转为字符串处理，成功解决了看似棘手的最大数拼接问题。这让我学到，面对非常规排序需求时，要勇于跳出数值比较的思维定式，灵活运用自定义比较函数和数据类型转换。

3.  **排序算法性能测试**：通过对多种经典排序算法（快速排序、归并排序、堆排序、希尔排序、插入排序、选择排序、冒泡排序）在不同数据规模和数据特性（随机、有序、逆序）下的性能进行测试，我直观地感受到了 O(N log N) 算法相对于 O(N?) 算法在效率上的压倒性优势，尤其是在大数据量下。同时也观察到，某些算法（如快速排序）在特定输入下（如已排序或逆序）可能性能退化，而另一些（如插入排序、冒泡排序优化版）在数据近乎有序时表现优异。这强调了在实际应用中，不仅要考虑平均时间复杂度，还要结合数据特征和最坏情况来选择或优化排序算法。此外，对空间复杂度、稳定性、是否原地排序等特性的理解也得到了加深。

4.  **序列（Top N 和）**：该实验处理的是一个组合数量可能爆炸性增长的问题 (N^M)。直接枚举不可行，这迫使我们寻找更精巧的策略。通过学习和实现，我掌握了使用优先队列（堆）来高效解决 Top K 问题的经典方法。逐行合并的思想，结合大顶堆动态维护当前最小的 n 个和，并利用有序性剪枝，有效地控制了时间和空间复杂度，避免了内存溢出。这让我体会到逐步构建解、利用合适的数据结构（堆）维护中间状态以及剪枝优化在处理复杂组合问题时的威力。

5.  **三数之和**：这个实验突显了"预处理"的重要性。通过首先对数组进行排序，使得后续利用双指针技术从 O(N?) 优化到 O(N?) 成为可能。双指针法在有序数组中查找满足特定和的元素对非常高效。同时，此题也强调了在处理包含重复元素的输入时，去重逻辑的严谨性至关重要，需要分别在固定第一个元素和找到解后进行判断和移动指针，以确保结果的唯一性。
