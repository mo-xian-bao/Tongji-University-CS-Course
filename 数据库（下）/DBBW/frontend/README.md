# ExCourt 前端重构说明

## 概述
前端采用白蓝简约配色风格，提供清爽舒适的用户体验。所有页面已经完成重构，使用现有后端API接口。

## 页面结构

### 1. 登录/注册页面 (`index.html`)
- 白蓝配色，简约设计
- 支持用户登录和注册
- 表单验证和错误提示

### 2. 主页 (`dashboard.html`)
- **左侧面板**：我的场地
  - 网格布局展示用户发布的场地
  - 每个场地显示为卡片，包含场地ID、日期、时间
  - 卡片hover有浮动效果
  - 可滚动查看所有场地
  
- **右侧面板**：场地广场
  - 列表形式展示所有已发布的场地
  - 每行显示一个场地的详细信息
  - 非本人发布的场地可以申请交换
  
- **底部导航栏**：四个按钮
  - 🏠 主页
  - ➕ 发布场地
  - 🔍 搜索场地
  - 👤 个人中心

### 3. 发布场地页面 (`post.html`)
- **两个功能标签**：
  - 发布已有场地：发布自己拥有的场地时间段
  - 发布需求场地：发布想要的场地时间段
  
- **表单字段**：
  - 场地ID
  - 日期（默认今天）
  - 开始时间
  - 结束时间
  
- 自动清空表单，实时反馈

### 4. 搜索场地页面 (`search.html`)
- **两个功能标签**：
  - 搜索已有场地
  - 搜索需求场地
  
- **搜索条件**（均可选）：
  - 场地ID
  - 日期
  - 开始时间
  - 结束时间
  
- **搜索结果**：
  - 显示匹配结果数量
  - 列表形式展示
  - 支持申请交换

### 5. 个人中心页面 (`profile.html`)
- **个人信息**：
  - 显示用户头像（首字母）
  - 显示用户名
  - 显示/编辑昵称（本地存储）
  
- **修改密码**：
  - 预留接口，待后端实现
  - 包含当前密码、新密码、确认密码字段
  - 完整的表单验证
  
- **退出登录**：
  - 清除本地认证信息
  - 跳转到登录页

## 使用的后端API

### 认证相关
- `POST /auth/register` - 用户注册
- `POST /auth/login` - 用户登录
- `GET /auth/me` - 获取当前用户信息

### 场地相关
- `POST /courts/owned/post` - 发布已有场地
- `POST /courts/owned/search` - 搜索已有场地
- `POST /courts/wanted/post` - 发布需求场地
- `POST /courts/wanted/search` - 搜索需求场地

### 交换相关
- `POST /exchange/request` - 申请交换场地

## 预留功能（后端未实现）

以下功能在前端已做好接口预留，等待后端实现：

1. **修改密码功能**
   - 前端路径：`profile.html` 中的修改密码表单
   - 预留接口：`POST /auth/change-password`
   - 所需参数：`current_password`, `new_password`

2. **昵称管理**
   - 目前使用本地存储
   - 未来可对接后端用户信息接口

## 设计特点

### 配色方案
- 主色：`#4a90e2`（蓝色）
- 背景：`#ffffff`（白色）
- 浅色背景：`#f8f9fb`
- 文本：`#2c3e50`（深灰）
- 次要文本：`#6b7280`（中灰）

### 交互效果
- 按钮hover有颜色变化和轻微上移
- 卡片hover有阴影和上移效果
- 表单输入focus有蓝色边框和阴影
- 平滑的过渡动画

### 响应式设计
- 支持移动端和桌面端
- 小屏幕下自动调整布局
- 底部导航栏固定在底部

## 注意事项

1. **只修改了前端**：所有修改仅限于前端代码，未修改任何后端代码
2. **使用现有API**：完全使用现有的后端API接口
3. **预留接口**：对于后端暂未实现的功能，前端已做好接口预留
4. **本地存储**：昵称等信息暂存在浏览器本地存储中
5. **认证管理**：使用JWT token进行身份验证

## 如何使用

1. 启动后端服务器
2. 访问 `http://localhost:port/` 进入登录页
3. 注册或登录账号
4. 使用底部导航栏切换不同功能页面
