# 运动场地交换系统设计报告

## 一、系统概述

运动场地交换系统（ExCourt）是一个基于Web的场地资源共享平台，旨在解决用户之间场地资源错配问题。系统采用前后端分离架构，后端使用FastAPI框架，数据库采用MongoDB NoSQL数据库，前端使用原生HTML5+CSS3+JavaScript实现。系统核心功能包括用户认证、场地信息发布、需求发布、智能匹配与交换申请等模块。

## 二、数据库设计

### 2.1 数据库选型

系统采用**MongoDB**作为主数据库，主要基于以下考虑：

1. **灵活的文档模型**：场地信息结构可能随需求变化，文档型数据库便于扩展
2. **高性能读写**：场地查询和匹配操作频繁，MongoDB的索引机制提供良好性能
3. **异步支持**：配合Motor异步驱动，与FastAPI异步框架完美配合
4. **部署便捷**：使用Docker容器化部署，开发和生产环境统一

### 2.2 数据库架构

数据库名称：`ExCourt`，包含以下4个核心集合（Collection）：

#### 2.2.1 用户集合（users）

存储用户账户信息，支持注册登录和身份验证。

```javascript
{
  _id: ObjectId,              // MongoDB自动生成的主键
  username: String,           // 用户名（唯一索引）
  password_hash: String,      // 密码哈希值
  salt: String,               // 密码加盐
  created_at: DateTime        // 注册时间
}
```

**索引设计**：
- `username`字段创建唯一索引，确保用户名不重复，同时加速登录查询

**安全设计**：
- 密码使用SHA-256哈希算法加密，加入随机盐值防止彩虹表攻击
- JWT Token机制实现无状态会话管理，有效期120分钟

#### 2.2.2 已有场地集合（owned_courts）

存储用户发布的已拥有场地信息，用于交换匹配。

```javascript
{
  _id: ObjectId,              // 文档主键
  username: String,           // 发布者用户名
  court_id: Integer,          // 场地编号（0-1000）
  start_at: DateTime,         // 开始时间（UTC）
  end_at: DateTime,           // 结束时间（UTC）
  created_at: DateTime        // 发布时间
}
```

**索引设计**：
- `[court_id, start_at]`复合索引：优化按场地和时间搜索的查询性能
- 查询场景：用户查找特定场地特定时间段的可交换资源

**数据约束**：
- `court_id`范围限制：0-1000
- 时间校验：`end_at`必须晚于`start_at`
- 所有时间统一使用UTC时区存储，避免时区混乱

#### 2.2.3 需求场地集合（wanted_courts）

存储用户发布的场地需求信息，用于匹配交换。

```javascript
{
  _id: ObjectId,              // 文档主键
  username: String,           // 需求者用户名
  court_id: Integer,          // 需求场地编号
  start_at: DateTime,         // 需求开始时间
  end_at: DateTime,           // 需求结束时间
  created_at: DateTime        // 发布时间
}
```

**索引设计**：
- `[court_id, start_at]`复合索引：与owned_courts对称设计，支持高效交叉匹配

**业务逻辑**：
- 用户可发布多条需求，系统自动与已有场地集合进行智能匹配
- 匹配算法：`court_id`、`start_at`、`end_at`三维度完全相同即为完美匹配

#### 2.2.4 交换请求集合（exchange_requests）

记录场地交换申请的完整生命周期。

```javascript
{
  _id: ObjectId,              // 请求主键
  post_user_name: String,     // 场地发布者
  request_user_name: String,  // 申请者
  court_id: Integer,          // 目标场地编号
  status: String,             // 状态：pending/completed/refused
  created_at: DateTime        // 申请时间
}
```

**状态流转**：
```
pending（待处理）→ completed（已完成）
                 → refused（已拒绝）
```

**查询优化**：
- 通过`post_user_name`查询收到的申请
- 通过`request_user_name`查询发出的申请
- `status`字段过滤不同状态的请求

### 2.3 数据库连接与初始化

系统使用Motor异步驱动连接MongoDB，关键配置如下：

```python
# 连接配置
MONGODB_URL: "mongodb://localhost:27017"
DATABASE_NAME: "ExCourt"
serverSelectionTimeoutMS: 5000  # 连接超时5秒
```

**初始化流程**：
1. 应用启动时调用`connect_to_mongo()`建立连接
2. 执行`ping`命令测试连接可用性
3. 调用`_ensure_indexes()`创建必要索引
4. 失败时打印警告但不中断服务，支持离线调试

### 2.4 数据一致性保障

虽然MongoDB不强制外键约束，但系统在应用层实现了数据一致性：

1. **用户存在性验证**：发布场地前验证JWT Token，确保用户已登录
2. **时间逻辑校验**：使用Pydantic validator确保`end_time > start_time`
3. **事务性操作**：交换请求与场地状态更新采用原子操作
4. **软删除机制**：暂未实现物理删除，保留历史数据便于审计

### 2.5 数据库性能优化

1. **索引策略**：
   - 用户名唯一索引：O(log n)登录查询
   - 场地复合索引：支持多维度快速检索
   
2. **查询优化**：
   - 使用`sort([("start_at", 1)])`返回有序结果
   - 日期范围查询使用`$gte`和`$lt`操作符
   - 避免全表扫描，所有查询均利用索引

3. **连接池管理**：
   - Motor自动管理连接池，默认最大连接数100
   - 异步IO避免阻塞，提升并发处理能力

## 三、后端架构设计

### 3.1 技术栈

- **框架**：FastAPI 0.100+（异步高性能）
- **ORM/ODM**：Motor（MongoDB异步驱动）
- **认证**：JWT Token + HS256算法
- **数据验证**：Pydantic（类型安全）

### 3.2 API路由设计

系统采用RESTful风格，主要路由包括：

| 路由                    | 方法 | 功能         | 认证 |
| ----------------------- | ---- | ------------ | ---- |
| `/auth/register`        | POST | 用户注册     | 否   |
| `/auth/login`           | POST | 用户登录     | 否   |
| `/courts/owned/post`    | POST | 发布已有场地 | 是   |
| `/courts/owned/search`  | POST | 搜索已有场地 | 否   |
| `/courts/wanted/post`   | POST | 发布需求场地 | 是   |
| `/courts/wanted/search` | POST | 搜索需求场地 | 否   |
| `/exchange/request`     | POST | 申请交换     | 是   |

### 3.3 安全机制

1. **密码安全**：SHA-256 + 随机盐值哈希
2. **会话管理**：JWT无状态Token，避免服务器存储会话
3. **权限控制**：`Depends(get_current_user)`装饰器保护需认证接口
4. **数据校验**：Pydantic模型自动验证请求参数，防止注入攻击

## 四、前端架构设计

### 4.1 技术选型

采用**原生Web技术栈**，无任何框架依赖：
- HTML5 + CSS3：响应式布局
- JavaScript ES6 Modules：模块化代码组织
- LocalStorage：Token和用户信息存储

### 4.2 核心功能模块

1. **认证模块**（auth.js）：登录注册、Token管理
2. **场地模块**（courts.js）：发布查询、智能匹配
3. **交换模块**：模态框交互、状态展示
4. **API封装**（api.js）：统一请求处理

### 4.3 UI设计

- **色彩方案**：白蓝配色（#4a90e2主色调）
- **布局方式**：双栏布局（我的场地/场地广场）
- **交互方式**：模态框弹窗、数据属性驱动

## 五、系统特色

1. **智能匹配算法**：前端实现三维完全匹配（场地+日期+时间）
2. **实时交互**：异步Ajax + 模态框无刷新体验
3. **容器化部署**：Docker一键启动MongoDB
4. **可扩展性**：NoSQL文档模型支持字段灵活扩展
