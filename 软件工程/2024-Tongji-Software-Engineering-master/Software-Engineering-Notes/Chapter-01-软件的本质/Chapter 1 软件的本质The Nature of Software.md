### 1.1.1 定义软件

(要理解）

软件是什么：

1. 完成软件的特性，功能，性能等所需要的 **计算机程序，指令代码——程序**
    - feature特性： *非功能需求*  non-functional：如安全性，兼容性，可移植性，可扩展性等
    - function功能：与非功能需求相对应
    - performance：feature的一部分，但因为很重要所以单拉出来
2. 使得程序可以充分利用操纵信息所使用的 **数据结构——数据**
3. 描述程序操作使用的硬拷贝和虚拟形式的 **描述性信息——文档**
#### 软件（Software）和程序（Program）联系但也有区别：

1. **软件（Software）**：
   - 软件是指计算机系统中的非硬件部分，包括程序、规程、规则以及与这些程序相关的文档和数据。
   - 软件可以分为系统软件和应用软件两大类。系统软件如操作系统、设备驱动程序等，它们为计算机硬件提供抽象层，使得用户和其他软件可以更容易地与硬件交互。应用软件则是为了帮助用户执行特定的任务，如文字处理、图像编辑、游戏等。
2. **程序（Program）**：
   - 程序是一组指令的集合，这些指令告诉计算机如何执行特定的任务。
   - 程序通常是为了解决特定问题或执行特定功能而编写的，它们可以是独立的，也可以是更大软件系统的一部分。

**区别**：

- **组成**：软件是一个更广泛的概念，它包括了程序、相关的文档、数据以及可能包含的其他资源。程序则是软件的一个组成部分，是实现特定功能的代码集合。

- **功能**：程序通常指的是执行特定任务的代码，而软件则可能包含多个程序，以及支持这些程序运行的环境和工具。

- **目的**：程序的编写通常是为了实现一个具体的功能或解决一个问题，而软件的开发则可能是为了提供一个完整的解决方案或服务。

### 1.1.2 软件应用领域

(软件的领域划分）

- System Software系统软件：操作系统软件（应用软件运行在这之上）——算法核心
- Application Software应用软件：解决特定需求的独立应用程序。
- Engineering/scientific Software工程/科学软件：例如matlab
- Embedded Software嵌入式软件：例如家电内部的，汽车内部的 ——操作系统特殊，硬件交互性强，错误较难以定义
- Product-line Software产品线软件：为不同用户提供特定功能
- Web/mobile App：browser-based
- AI Software人工智能软件：机器人，博弈，模式识别（语音图像），自动驾驶，自然元素处理（文本）

### 1.1.3 遗留软件Legacy Software

(重要）

特点：年龄大(太老了），业务关键性（数据难以移植，风险大，很少重新开发）

描述：**1.老旧软件； 2. 不断变更以适配需求——臃肿； 3. 质量差，代码可读性差，文档混乱**

**Web 应用（WebApp）的发展历程**

- **早期阶段 (Web 1.0)**：
- 在万维网的早期（大约 1990 年到 1995 年），网站主要由一组**超文本链接文件**组成，使用文本和有限的图形来呈现信息 [1]。
- 这个阶段的 Web 应用主要用于**信息展示**，用户与网页的交互非常有限。
- **中期发展 (Web 2.0)**：
- 随着时间推移，HTML 通过 **XML 和 Java** 等开发工具得到增强，使得 Web 工程师能够提供计算能力以及信息内容 [1]。
- **Web 应用程序**诞生，用户可以进行更多的交互操作，如在线购物、社交互动等。
- **语义网 (Web 3.0)**：
- 在过去十年中，**语义网技术**（通常被称为 Web 3.0）已经发展成为复杂的企业和消费者应用程序 [2]。
- **HTML5/CSS/JS** 等技术进一步提升了 Web 应用的功能和用户体验 [2]。
- 这个阶段的 Web 应用更加注重**数据之间的关联和语义理解**，为用户提供更加智能化的服务。
- **Web 应用的特点**：
- **用户界面**：Web 应用通常会建立一个用户界面，允许用户进行交互 [3]。
- **互操作性**：Web 应用可以与基于 Web 的资源进行互操作 [3]。
- **本地处理能力**：部分 Web 应用也具备一定的本地处理能力 [3]。
- **WebApp 与 Mobile App 的区别**：
- **WebApp**：允许移动设备通过专门设计的**浏览器**访问基于 Web 的内容 [4]。
- **Mobile App**：可以直接访问设备的**硬件特性**（如加速计或 GPS 定位），并提供本地处理和存储功能 [4]。
- **Web 应用的架构**：
- Web 应用的架构通常包括**前端**和**后端**服务 [5]。
- **前端**包括客户端（用户）设备和允许访问后端的应用软件（如浏览器）[5]。
- **后端**包括服务器和相关的计算资源、数据存储系统（如数据库）[5]。
- **Web 应用的演变**：
- Web 应用从最初的简单信息展示发展到复杂的交互式应用程序，并不断朝着智能化和个性化方向发展。
- Web 技术的进步推动了 **WebApp、移动应用和云计算**等多种形式的软件发展 [1-4, 6].

- **移动设备Mobile Application**

在大多数情况下，移动应用程序包含用户界面、与基于 Web 的资源的互操作性和本地处理能力( 对本地的存储和信息进行计算处理 )，还可提供长久的存储能力；移动网络应用程序和移动应用程序之间存在细微的区别：前者浏览器，后者可以直接获取设备硬件信息提供本地处理与存储能力

在大多数例子中，移动应用建立一个user interface，以及和网页资源的可交互性(interoperability)和本地处理能力

好的，根据您提供的资料和我们之前的对话，我将介绍云计算的相关概念，并突出关键信息：

**云计算 (Cloud Computing) 的概念**

- **定义**：云计算是一种基础设施或“生态系统”，它允许任何地方的任何用户使用计算设备来**大规模地共享计算资源**。
- **逻辑架构**：
    - **外部计算设备**：用户通过各种设备访问云端资源。
    - **云端资源**：云端提供多种资源，包括：
        - **软件即服务（SaaS）**：用户可以直接使用的应用程序。
        - **平台即服务（PaaS）**：为用户提供开发和部署应用程序的平台。
        - **基础设施即服务（IaaS）**：提供计算、存储和网络等基础资源。
    - **访问方式**：
        - 用户可以通过 **Web 浏览器** 访问云端。
        - 设备可以访问云端的 **可执行应用程序**，替代本地设备上的应用程序。
- **云计算的实现**：
    - 需要开发一个包含**前端和后端服务**的架构。
    - **前端**：包括客户端（用户设备）和允许访问后端的应用程序（如浏览器）。
    - **后端**：包括服务器和相关的计算资源、数据存储系统（如数据库）、服务器驻留的应用程序、以及使用中间件来协调和监控流量的管理服务器。
- **云计算的特点**：
    - **资源共享**：用户可以按需使用云端的计算资源，无需购买和维护自己的硬件.
    - **灵活性**：云平台可以根据用户的需求动态地调整资源分配.
    - **可扩展性**：可以根据业务需求扩展或缩减计算资源.
    - **可访问性**：用户可以通过互联网随时随地访问云端资源.
    - **多样化的访问级别**：云计算架构可以分段提供不同级别的访问权限，从完全公开访问到仅限授权用户访问的私有云架构。

**云计算在软件工程中的应用**

- **部署方式**：云计算是软件部署的一种方式，可以使软件更容易被访问和使用。
- **微服务架构**：云计算常与微服务架构结合使用，将整个 Web 应用组织为一系列小的 Web Service，这些小的 Web Service 可以独立编译部署，并通过各自的 API 接口相互通信，彼此相互协作，作为一个整体为用户提供服务，但可以独立进行扩展。
    - **优点**：一个微服务出错不会影响其他。
- **云平台**：
    - **IaaS 层**：提供虚拟机等资源。
    - **PaaS 层**：提供资源监测、预警、优化决策等平台服务。
    - **SaaS 层**：提供软件和可视化界面。

**云计算与 Web 应用的联系**

- **Web 应用的演变**：Web 应用的发展推动了云计算的发展，反之亦然，云计算为 Web 应用提供了强大的基础设施支持。
- **移动应用**：移动应用可以通过云计算访问云端的资源和服务，实现更强大的功能。

云平台:IaaS层（资源层)-虚拟机（跨IaaS与PaaS）->Paas层（平台层：资源监测；预警；优化决策)-->SaaS层(软件，可视化界面)
