# 七、文件管理 复习总结

## 第一部分：文件系统静态结构
*这部分主要关注文件存放在磁盘上时的样子（持久化数据结构）。*

### 1. 磁盘布局（Unix V6++ 风格）
一个文件卷（File System Volume）在物理磁盘上通常分为三个主要区域（从低地址到高地址）：

1.  **超级块 (SuperBlock)**
    *   **位置**：0#、1# 扇区（通常引导扇区占一部分，超级块紧随其后）。
    *   **作用**：文件系统的“总指挥部”，存放文件系统的全局配置信息和**空闲资源管理信息**。
    *   **核心内容**：
        *   文件系统的大小、Inode区大小。
        *   **空闲资源栈**：
            *   `s_inode`：空闲 DiskInode 号栈（直接缓存一部分可用的 Inode 号）。
            *   `s_free`：空闲盘块号栈（成组链接法的栈顶）。
        *   状态标记（如 `s_fmod` 脏标记，指示超级块是否需要写回磁盘）。

2.  **Inode 区 (索引节点区)**
    *   **位置**：从 2# 扇区开始，占据若干连续扇区。
    *   **内容**：存放所有的 **DiskInode**（文件控制块 FCB）。
    *   **特点**：每个文件（包括目录）都在磁盘上有且仅有一个 DiskInode。Unix 将文件的**元数据**（属性）和**文件名**分开存放，Inode 存元数据。

3.  **数据区 (Data Area)**
    *   **位置**：Inode 区之后的所有扇区。
    *   **内容**：
        *   **普通文件**的数据块。
        *   **目录文件**的数据块（存放目录项）。
        *   **间接索引块**（存放巨大的文件所需的索引表）。
        *   **空闲盘块**。

### 2. 文件控制块 (DiskInode)
*文件ID（i_number）就是 DiskInode 在数组中的下标。*

*   **核心字段**：
    *   `d_mode`：文件类型（目录/普通/设备）和访问权限（rwx）。
    *   `d_nlink`：硬链接计数（有多少个目录项指向这个 Inode）。
    *   `d_uid`/`d_gid`：文件拥有者和组 ID。
    *   `d_size`：文件大小（字节数）。
    *   **`d_addr` (混合索引表)**：最关键的字段，用于建立 **逻辑块 (Logical Block) -> 物理块 (Physical Block)** 的映射。

*   **混合索引树结构 (Unix V6++)**：
    *   **直接寻址**：`d_addr[0] ~ [5]`，直接存放物理盘块号。用于存小文件。
    *   **一次间接寻址**：`d_addr[6] ~ [7]`，存放**索引块**的号。索引块中存放物理盘块号。
    *   **二次间接寻址**：`d_addr[8] ~ [9]`，存放**二级索引块**的号。二级索引块指向一级索引块，一级指向数据块。用于存超大文件。

### 3. 目录结构与目录文件
*   **目录项 (Directory Entry)**：
    *   Unix 中，文件名不包含在 Inode 中，而是存放在**目录项**里。
    *   结构：`文件名` + `Inode号` (i_number)。
    *   大小：固定大小（如 16字节 或 32字节）。
*   **目录文件**：
    *   目录本身也是一个文件。
    *   它的“数据”就是**一系列目录项**。
    *   **特殊目录项**：
        *   `.` (当前目录)。
        *   `..` (父目录，用于实现相对路径跳转)。

### 4. 空闲资源管理 (重点逻辑)
*   **空闲 Inode 管理**：
    *   使用 **栈 (Stack)** 方式。
    *   超级块中维护一个数组 `s_inode` 作为栈，存放最多 100 个空闲 Inode 号。
    *   **分配**：从栈顶弹出一个号。若栈空，则扫描磁盘 Inode 区寻找新的空闲节点填充栈（可能有优化策略）。
    *   **回收**：将 Inode 号压入栈。

*   **空闲盘块管理**：
    *   使用 **成组链接法 (Group Linked List)**（结合了栈和链表的优势）。
    *   **原理**：
        *   超级块中的 `s_free` 数组作为**第一组**空闲盘块号栈（最多 100 个）。
        *   `s_free[0]` (栈底元素) 指向**下一组**空闲盘块的索引块（即下一个组长块）。
        *   下一组的索引块中又记录了 100 个空闲块号，且第一个指向再下一组。
    *   **分配**：从超级块栈顶弹出。如果弹出的刚好是栈底（组长块），则先把该块中记录的下一组信息读入超级块，再分配该块。
    *   **回收**：压入超级块栈。如果栈满了（100个），则把当前超级块的栈写入刚回收的这个盘块，使其成为新的组长块，然后清空超级块栈指向它。

## 第二部分：文件系统的使用
*这部分主要关注内存中的数据结构和运行时流程。*

### 1. 打开文件结构 (三级映射表 - 必考点)
进程访问文件时，内核通过三层数据结构来管理：

1.  **进程级：打开文件描述符表 (User File Descriptor Table)**
    *   位于进程的 `User` 结构（或 PCB）中。
    *   **文件描述符 (fd)** 就是这个数组的**下标**。
    *   **内容**：指向系统打开文件表 (`File` 结构) 的指针。

2.  **系统级：打开文件表 (Open File Table / File Structure)**
    *   全局唯一的表（或动态分配的结构链表）。
    *   **核心内容**：
        *   `f_offset`：**读写指针**（当前读写到文件的哪个位置）。**注意：这是会话级别的，父子进程共享，不同进程打开同一文件不共享。**
        *   `f_flag`：打开模式（读/写/读写）。
        *   `f_count`：引用计数（有多少个 fd 指向它）。
        *   `f_inode`：指向内存 Inode 的指针。

3.  **系统级：内存 Inode 表 (InMemory Inode Table)**
    *   是磁盘 DiskInode 在内存中的副本。
    *   **核心内容**：
        *   DiskInode 的所有属性。
        *   `i_count`：引用计数（有多少个 File 结构指向它）。
        *   `i_lock`：互斥锁（防止多进程同时修改元数据）。
        *   `i_flag`：状态标记（如脏标记，指示 Inode 是否需写回磁盘）。
    *   **共享性**：无论多少个进程打开同一个文件，内存中只有**一个**对应的内存 Inode。

### 2. 目录搜索 (Namei 过程)
*如何根据路径名 `/home/user/file` 找到对应的 Inode？*

1.  **确定起点**：
    *   如果是绝对路径（`/` 开头）：从**根目录 Inode** 开始。
    *   如果是相对路径：从当前进程的**工作目录 Inode** (`u_cdir`) 开始。
2.  **逐层解析**：
    *   读取当前目录的数据块。
    *   在目录项中线性搜索匹配的文件名（如 `home`）。
    *   找到后获取其 Inode 号。
    *   通过 `IGET` 操作载入下一级目录的 Inode。
    *   重复上述步骤，直到路径结束。
3.  **结果**：返回目标文件的内存 Inode 指针。

### 3. 系统调用的执行过程 (核心流程)

#### A. `fd = open(path, mode)`
1.  **解析路径**：调用 `Namei` 根据 `path` 搜索目录，找到目标文件的 Inode。
    *   如果文件不存在且 mode 为创建，则分配新 Inode。
2.  **分配资源**：
    *   在**系统打开文件表**中分配一个空闲的 `File` 结构。
    *   在进程的**文件描述符表**中分配一个空闲的 `fd`。
3.  **建立关联**：
    *   `fd` 指向 `File` 结构。
    *   `File` 结构指向 Inode。
    *   初始化 `File` 的 `f_offset = 0`，`f_flag = mode`。
    *   Inode 的引用计数 `i_count++`。
4.  **返回**：返回 `fd` 给用户。

#### B. `n = read(fd, buf, size)`
1.  **参数校验**：通过 `fd` 找到 `File` 结构，检查是否有读权限 (`FREAD`)。
2.  **确定位置**：获取当前的读写指针 `f_offset`。
3.  **逻辑地址转换**：
    *   计算 `f_offset` 对应的**逻辑块号 (lbn)** 和 **块内偏移 (offset)**。
    *   查 Inode 的索引表 (`Bmap`)，将 `lbn` 转换为物理块号 (`bn`)。
4.  **读数据 (IO 操作)**：
    *   请求缓存层读入物理块 `bn`。
    *   **缓存命中**：直接使用。
    *   **缓存不命中**：启动磁盘 IO (`Bread`)。
    *   **预读优化**：如果是顺序读，可能同时启动下一块的异步预读 (`Breada`)。
5.  **数据传输**：将缓存块中从 `offset` 开始的数据复制到用户空间的 `buf`。
6.  **更新状态**：`f_offset += 实际读入字节数`。
7.  **循环**：如果 `size` 跨越多个块，重复上述步骤。

#### C. `n = write(fd, buf, size)`
1.  **参数校验**：通过 `fd` 找到 `File` 结构，检查写权限。
2.  **确定位置**：获取 `f_offset`。
3.  **逻辑地址转换**：计算 `lbn` 和 `offset`。
    *   如果该逻辑块尚未分配物理块，则此时**分配物理块**并更新索引表。
4.  **写数据 (缓存交互)**：
    *   **整块写 (512字节)**：不需要读旧数据，直接申请空闲缓存块 (`GetBlk`)，覆盖写入。
    *   **部分写 (<512字节)**：必须先将磁盘上的旧数据读入缓存 (`Bread`)，修改对应部分（读-改-写）。
5.  **数据传输**：将用户空间 `buf` 的数据复制到缓存块。
6.  **延迟写/异步写**：
    *   如果缓存块**写满**了：发起异步写 (`Bawrite`)，立刻放入 IO 队列，进程不等待。
    *   如果**没写满**：标记为脏（延迟写 `Bdwrite`），暂留内存，等待后续写入合并。
7.  **更新状态**：`f_offset += 写入字节数`。如果文件变大，更新 Inode 的 `i_size`。

#### D. `lseek(fd, offset, whence)`
*   这是一个纯内存操作，**不产生磁盘 IO**。
1.  通过 `fd` 找到 `File` 结构。
2.  根据 `whence`（从头、当前、末尾）计算新的位置。
3.  修改 `File` 结构中的 `f_offset` 字段。

#### E. `close(fd)`
1.  清空进程描述符表中 `fd` 的指向。
2.  **释放 File 结构**：`File->f_count--`。
    *   如果 `f_count` 降为 0，说明没有进程在用这个会话了，释放 `File` 结构。
3.  **释放 Inode**：`File` 释放时，会导致 `Inode->i_count--`。
    *   如果 `Inode->i_count` 降为 0，说明内存中没有进程打开该文件了。
    *   如果 Inode 被修改过（脏），将其内容写回磁盘 Inode 区。
    *   释放内存 Inode。

### **第 2 页：基本概念（文件与元数据）**
*   **文件定义**：可重复访问的**字节序列**。支持随机访问。
*   **元数据 (Metadata) —— 必考词汇**：
    *   **定义**：为了管理用户文件而设计的数据结构。
    *   **核心**：每个文件都有一个**文件控制块 (FCB)**。它记录了权限、数据在哪等信息。
    *   **存放在哪？** 元数据和用户数据都存在同一张磁盘上。
*   **精讲**：文件系统 = 很多文件 + 管理这些文件的元数据。

---

### **第 3 页：逻辑块 vs 物理块**
*   **切块存储**：文件太大，磁盘不能一次给一整块连续空间，所以要“切块”。
    *   **逻辑块 (bn)**：用户看文件是从第 0 字节开始的序列，按每 512 字节切开，叫逻辑块 0, 1, 2...
    *   **物理块 (dn)**：磁盘上的真实扇区。
*   **离散存储**：
    *   相邻的逻辑块（比如文件的第1块和第2块）在磁盘物理位置上**不必相邻**。
*   **Unix V6++ 关键参数**：磁盘块大小 = **512 字节**。
    *   *例题*：1000 字节的文件占 2 个逻辑块。实际占用 1024 字节物理空间（最后一块不满也要占 512 字节）。

---

### **第 4 页：文件控制块 (FCB)**
这是操作系统管理文件的“档案”，包含以下核心信息：
1.  **文件名与尺寸**。
2.  **地址映射表**：最关键！记录了“逻辑块 $bn$ 对应哪个物理块 $dn$”。公式：$dn = f(bn)$。
3.  **所有者**：`uid`（用户ID）。
4.  **访问权限**：
    *   Unix 风格：**`RWXRWXRWX`**（文件主、组用户、其他人的 读/写/执行 权限）。
5.  **时间戳**：创建、访问、修改时间。

---

### **第 5 页：FCB 的创建**
*   **系统调用**：**`create(文件名, mode)`**。
*   **动作**：
    1.  在磁盘上新分配一个 FCB 空间。
    2.  填入文件名、`uid`。
    3.  设置初始长度为 0。

---

### **第 6 页：FCB 的使用（系统调用链路）**
文件操作的一生：
1.  **`open`**：把磁盘上的 FCB **读入内存**。检查当前用户有没有权限打开它。
2.  **`read / write`**：利用 FCB 里的**地址映射表**，算出要去磁盘哪个扇区读写，然后调用底层驱动（`bread/bwrite`）。
3.  **`close`**：如果改了文件，要把内存里更新后的 FCB **写回磁盘**。

---

### **第 7 页：Unix 的天才设计 —— Inode (索引节点)**
*   **传统做法 (Windows)**：文件名和文件属性全塞在目录项里。
*   **Unix 做法（必考区别）**：**分离存储**。
    *   **目录项 (Directory Entry)**：只存 **[文件名]** 和 **[Inode号]**。
    *   **Inode (索引节点)**：存除了文件名以外的**所有属性**（权限、大小、物理块号）。
*   **意义**：目录文件会变小，搜索文件的速度极大提高。

---

### **第 8 页：文件树与目录文件**
*   **结构**：树状结构。
    *   **叶子节点**：普通数据文件。
    *   **非叶子节点**：目录文件（特殊的文件夹）。
*   **目录项**：文件树上的“边”。每条边连接父目录和子文件。

### **第 9 页：Unix 的目录文件（内部结构）**
*   **核心逻辑**：目录在 Unix 中也是一个**文件**，只不过它的内容是固定的记录格式。
*   **`DirectoryEntry` 结构体（必背）**：

*   **特殊目录项**：
    *   **`.` (点)**：指向**本目录**。
    *   **`..` (点点)**：指向**父目录**。这保证了你可以沿树向上爬，支持“相对路径”。
*   **精讲**：每一条记录 32 字节，就像一张表格，左边是名字，右边是去哪找这个人的 ID。

### **第 11 页：绝对路径 vs 相对路径**
*   **绝对路径**：从根目录 `/` 开始（如 `/home/John/b`）。
*   **相对路径**：从**当前工作目录 (`u_cdir`)** 开始。
*   **机制**：内核在 `user` 结构里维护 `u_cdir` 指针。
*   **优势**：相对路径能减少目录搜索次数，提升效率。执行 `cd` 命令本质上就是修改内核中的这个指针。

---

### **第 12 页：DiskInode —— 磁盘上的文件控制块（重难点）**
每个文件在磁盘上都有一个 64 字节的档案：
1.  **`d_mode`**：16 位位图。
    *   最高位：是否已被分配。
    *   中间：文件类型（普通文件 `00`、目录文件 `10`、字符设备 `01`）。
    *   低位：`RWX` 权限。
2.  **`d_nlink`**：硬链接数。
3.  **`d_size`**：文件大小（字节）。
4.  **`d_addr[10]`**：**地址映射表**。这是文件的“肉身”所在。
*   **精讲**：Inode 号其实就是这个结构在磁盘 Inode 区的数组下标。

---

### **第 13 页：硬链接 vs 软链接（必考简答）**
*   **硬链接 (Hard Link)**：
    *   多个文件名指向**同一个 Inode 号**。
    *   Inode 里的 `d_nlink` 会增加。只有当 `d_nlink` 减到 0 时，文件才真正被删除。
*   **软链接 (Soft Link / 快捷方式)**：
    *   这是一个独立的小文件，内容是目标文件的**路径名**。
    *   有自己的 Inode，有自己的数据块。如果原文件删了，软链接就失效了。

---

### **第 14 页：文件卷 (File Volume) 的布局**
Unix V6 把磁盘划分为三个功能区（必考填空）：
1.  **超级块 (SuperBlock)**：0#、1# 扇区。存放整个文件系统的“配置单”和空闲资源信息。
2.  **Inode 区**：从 2# 扇区开始。存放所有的 `DiskInode`。
3.  **数据区**：存放文件的真实内容、目录内容以及索引块。

---

### **第 15 页：超级块 (SuperBlock) 结构**
这是文件系统的“大脑”，记录了：
*   `s_isize`：Inode 区占了多少块。
*   `s_fsize`：整个卷的大小。
*   **`s_free[100]` / `s_nfree`**：**空闲数据块**的管理栈（成组链接法）。
*   **`s_inode[100]` / `s_ninode`**：**空闲 Inode** 的缓存栈。
*   `s_fmod`：脏标志（如果改了内存里的超级块，要刷回磁盘）。

---

### **第 16 页：Inode 区的物理排布（计算点）**
*   **规格**：1 个 Inode 占 64 字节。
*   **扇区容量**：1 个扇区 512 字节，正好能放 $512 \div 64 = \mathbf{8}$ **个 Inode**。
*   **物理位置公式**：
    *   给一个 Inode 号 $n$，它在哪个扇区？
    *   **扇区号 = $n / 8 + 2$**（因为 Inode 区从 2# 开始）。
    *   **扇区内偏移 = $(n \pmod 8) \times 64$**。

1.  **目录搜索过程**：从 Inode 1（根）开始，读数据块找名字，拿 Inode 号，再读下级 Inode，循环直到终点。
2.  **Inode 属性**：除了文件名，啥都在 Inode 里。Inode 大小是 64 字节，一个扇区放 8 个。
3.  **文件卷结构**：超级块（0-1）-> Inode区（2-N）-> 数据区。
4.  **硬链接**：共享 Inode，不能跨文件系统。

### **第 17 页：文件长啥样？**
*   在 Unix 中，一切皆文件。主要分为三类：
    1.  **普通数据文件**：存你的文本、代码、照片。
    2.  **目录文件**：存文件名和 Inode 号的映射表。
    3.  **特殊文件**：代表硬件设备（如键盘、磁盘）。

### **第 18-19 页：混合索引树 (Hybrid Index Tree) —— 核心重难点**
这是 Inode 中 `d_addr[10]` 数组的奥秘。为了兼顾“小文件访问快”和“支持大文件”，Unix 采用了这种不均匀的结构：

1.  **直接索引 (`d_addr[0]` ~ `d_addr[5]`)**：
    *   前 **6 个** 元素直接存物理块号。
    *   **能存多大？** $6 \times 512 \text{B} = \mathbf{3KB}$。
    *   **优点**：读极小的文件只需 1 次磁盘 IO（读 Inode 后直接读数据）。

2.  **一级间接索引 (`d_addr[6]` ~ `d_addr[7]`)**：
    *   这 2 个元素存的是**“索引块”**的块号。
    *   **计算**：一个索引块 512 字节，存 4 字节的地址，能放 **128 个** 物理块号。
    *   **容量**：$2 \times 128 \times 512 \text{B} = \mathbf{128KB}$。

3.  **二级间接索引 (`d_addr[8]` ~ `d_addr[9]`)**：
    *   这 2 个元素存的是“一级索引块”的地址。
    *   **结构**：Inode $\rightarrow$ 一级索引块 (128个项) $\rightarrow$ 二级索引块 (128个项) $\rightarrow$ 数据块。
    *   **容量**：$2 \times 128 \times 128 \times 512 \text{B} = \mathbf{16MB}$。

*   **总结**：`d_addr` 像一把梯子，文件越大，爬得越深，访问越慢。

---

### **第 20 页：实例分析 —— 1000 字节的文件**
*   **计算**：
    *   逻辑块 0：0-511 字节。
    *   逻辑块 1：512-999 字节。
*   **Inode 填充**：
    *   `d_size = 1000`。
    *   `d_addr[0]` = 物理块 29。
    *   `d_addr[1]` = 物理块 30。
    *   其余 `d_addr` 全为 0。
*   **结论**：小文件只用直接索引。

---

### **第 21 页：实例分析 —— 4000 字节的文件**
*   **计算**：$4000 \div 512 \approx 7.8$。需要 **8 个** 物理块。
*   **分配方案**：
    *   `d_addr[0] ~ [5]` 占满了（前 6 块）。
    *   剩下的 2 块（第 6、7 逻辑块）必须放到 **一级间接索引** 里。
    *   **Inode 填充**：`d_addr[6]` 指向一个新分配的“索引块”（例如 35# 扇区），在这个 35# 扇区里，前两个位置填上那最后 2 块的物理块号。

---

### **第 22-23 页：磁盘上的目录文件（深挖）**
*   **类型标识**：`d_mode` 的文件类型位为 **`10`**。
*   **物理本质**：目录文件在磁盘上也有 Inode，也有自己的数据块（由 `d_addr` 指向）。
*   **内容**：它的数据块里存的就是一串 `DirectoryEntry`（文件名 + Inode号）。
*   **例子**：目录 `John` 包含文件 `a` 和 `b`。
    *   读 `John` 的 Inode $\rightarrow$ 找它的数据块 $\rightarrow$ 看到 `a` 对应 Inode 56，`b` 对应 Inode 50。

---

### **第 24 页：特殊文件（设备文件）**
*   **类型标识**：`d_mode` 为 **`01`**（字符设备）或 **`11`**（块设备）。
*   **特殊之处**：设备文件**没有数据块**。
*   **`d_addr[0]` 的妙用**：它不存物理块号，而是存 **[主设备号 | 从设备号]**。
    *   例如：`d_addr[0] = major | minor`。
*   **意义**：当你 `open("/dev/tty1")` 时，内核读到 Inode，发现是设备，就去调对应驱动程序的代码。

    *   答：$6$ (直接) + $128$ (一级1) + $66$ (一级2)。所以用到 **一级间接索引**。
2.  **目录文件的搜索逻辑**：文件名 $\rightarrow$ 目录项 $\rightarrow$ Inode 号 $\rightarrow$ 物理块。
3.  **设备文件的 Inode**：记住它不存数据，`d_addr` 存的是**设备号**。
4.  **文件类型码**：`00`普通，`10`目录，`01/11`设备。

### **第 25 页：磁盘资源管理概览**
*   **Inode 区管理**：
    *   **单位**：64 字节的 `DiskInode`。
    *   **空闲标志**：看 `d_mode` 里的 `IALLOC` 位。
    *   **优化**：为了不用每次都扫描整个 Inode 区，超级块里设了一个 **“空闲 Inode 栈”**，存着 100 个随拿随用的 Inode 号。
*   **数据区管理**：
    *   **单位**：512 字节的物理块。
    *   **机制**：使用 **“成组链接法”**。
*   **位置计算（必考公式）**：
    *   $n\#$ Inode 的扇区号 = $n / 8 + 2$。
    *   扇区内偏移 = $(n \pmod 8) \times 64$。

---

### **第 26 页：超级块 (SuperBlock) 里的账本**
超级块是常驻内存的，里面有两张重要的清单：
1.  **`s_free[100]`**：空闲磁盘块号栈。
2.  **`s_inode[100]`**：空闲 Inode 号栈。
*   **注意**：这两个栈都是为了提高效率。当栈空了，系统才会去磁盘深处寻找更多的空闲资源来补充。

---

### **第 27 页：空闲 Inode 的分配 (`ialloc`) 与回收 (`ifree`)**
*   **分配 (`ialloc`)**：
    *   直接从 `s_inode` 栈顶弹出一个号。
    *   **如果栈空了**：内核会扫描磁盘 Inode 区，找前 100 个空闲的 Inode 填满这个栈。
*   **回收 (`ifree`)**：
    *   把 Inode 号压回 `s_inode` 栈。
    *   **如果栈满了（>100个）**：直接丢弃这个号（反正磁盘上 `IALLOC` 位已经清零了，下次扫描还能找回来）。

---

### **第 28 页：成组链接法 (Group Linking Method) —— 核心重难点**
这是管理数以万计空闲磁盘块的绝妙方法。

*   **结构**：
    *   把所有空闲块按 **100个一组** 分成很多组。
    *   **组长**：每组的最后一个块。
    *   **关键点**：**上一组的“组长块”里，记录了下一组所有成员的块号。**
    *   **超级块**：只记录当前第一组的块号。
*   **形象理解**：就像接力赛。超级块手里拿一张纸，写着 100 个人的名字。最后那个人手里又揣着下一批 100 个人的名单。

---

### **第 29 页：成组链接法的分配与回收（算法细节）**
*   **分配 (`Alloc`)**：
    1.  从超级块 `s_free` 栈顶取一个号。
    2.  **特殊情况**：如果取走的是**组长**（即栈里最后一个号），说明这组用完了。
    3.  **动作**：把这个组长块里的“下一组名单”**复制到超级块中**。
*   **回收 (`Free`)**：
    1.  如果 `s_free` 没满，直接压栈。
    2.  **如果满 100 个了**：
        *   把超级块里这 100 个号**拷进当前准备回收的这个块**里。
        *   把这个块设为新的“组长”。
        *   超级块清空，只存这一个新组长的块号。

---

### **第 30 页：删除文件 A 的综合练习**
*   **场景**：删除一个 Inode 为 66，占用块为 1150, 1151... 的文件。
*   **变化**：
    1.  Inode 66 被压入超级块的 `s_inode` 栈。
    2.  块号 1150 等被压入超级块的 `s_free` 栈。
    3.  超级块标记为“脏”（`s_fmod = 1`）。

### **第 2 页：文件系统的完整生命周期**
一个文件系统从“冷”到“热”再到“冷”的过程：
1.  **使用前装载 (`mount`)**：
    *   **关键动作**：将磁盘上的**超级块 (SuperBlock)** 和 **根目录 Inode** 读入内存。
    *   **原因**：内核必须拿到超级块才能分配空闲块；拿到根目录才能开始查找路径。
2.  **使用阶段**：
    *   **维护文件树**：创建 (`creat`)、删除 (`unlink`)、打开 (`open`)。
    *   **数据读写**：`read`、`write`。
3.  **使用完毕卸载 (`unmount`)**：
    *   **关键动作**：将内存中变脏的超级块和所有缓存数据写回磁盘。

---

### **第 3 页：元数据的内存镜像**
*   **核心逻辑**：磁盘读写太慢，所以所有元数据（超级块、Inode、目录项）在被频繁访问前，都必须**先复制到内存里**。
*   **一致性问题**：在内存中改了，最后一定要记得刷回磁盘。

---

### **第 4 页：系统级核心数据结构（必背！）**
为了管理全系统所有进程打开的文件，内核维护了两个全局表：

1.  **内存 Inode 表 (`g_InodeTable`)**：
    *   **本质**：磁盘 `DiskInode` 的内存缓存。
    *   **作用**：只要全系统有一个进程在访问某个文件，该文件的 Inode 就必须在这张表里。
    *   **容量**：通常固定（如 100 项）。

2.  **系统打开文件表 (`g_OpenFileTable`)**：
    *   **本质**：记录全系统所有的**“文件会话”**。
    *   **结构**：由很多 `File` 结构组成。
    *   **作用**：它像一个中转站，连接进程和内存 Inode。

---

### **第 5 页：内存 Inode (`Inode` 类) 详解**
这是 Inode 的内存增强版，除了磁盘上的属性（大小、地址表），还多了：
*   **`i_count` (引用计数)**：当前有多少个 `File` 结构指向我。当 `i_count == 0` 时，这个 Inode 可以从内存表里删掉。
*   **`i_flag` (标志位)**：
    *   `ILOCK`：正在读写，加锁。
    *   `IUPD`：被改过了，需要同步回磁盘。
*   **`i_dev`, `i_number`**：文件的“身份证”，用来标识这个内存副本是从磁盘哪个扇区搬来的。

---

### **第 6 页：文件系统会话 (Session)**
*   **概念**：从 `open` 开始，到 `close` 结束，叫一次会话。
*   **核心特征**：**读写指针 (Offset)**。
    *   文件被看作是线性的字符流。
    *   你读了 10 字节，指针就往后挪 10 字节。
    *   **重点**：不同的进程，甚至同一进程多次 `open` 同一个文件，通常拥有**独立**的读写指针。

---

### **第 7 页：`File` 结构体 —— 会话的载体**
这是 `g_OpenFileTable` 里的元素，记录了某个具体会话的信息：
*   **`f_flag`**：你当时是怎么打开的？（只读 `FREAD`、只写 `FWRITE`）。
*   **`f_count`**：有多少个进程共享这个会话？（通常是 1，除非 `fork` ）。
*   **`f_inode`**：指针，指向对应的**内存 Inode**。
*   **`f_offset` (重点)**：该会话当前的**读写位置**。

---

### **第 8 页：进程级数据结构 —— `u_ofiles` 与 `fd`**
这是距离程序员最近的一层，存在进程的 `user` 结构里。

1.  **进程打开文件表 (`u_ofiles`)**：
    *   **本质**：一个指针数组，长度通常只有 **15**。
    *   **内容**：存的是指向全局 `File` 结构的**指针**。
2.  **文件描述符 (fd)**：
    *   **本质**：就是这个数组的**下标**。
    *   当你执行 `read(3, ...)` 时，内核其实是去找 `u_ofiles[3]` 指向的那个 `File` 结构。

---

### **本节复习总结（必考逻辑链条）**

**如果你想在文件里读一个字符，内核是怎么顺藤摸瓜的？（背诵路径）：**

1.  **第一步**：拿用户给的 **fd**（下标），去进程的 **`u_ofiles`** 里找到 **`File` 指针**。
2.  **第二步**：在 **`File` 结构**里，看到当前的 **`f_offset`**，并找到指向 **`内存Inode`** 的指针。
3.  **第三步**：在 **`内存Inode`** 里，根据 `f_offset` 查 **`i_addr` 地址表**，算出磁盘上的**物理块号**。
4.  **第四步**：调用驱动，把数据读入**缓存 (Buffer)**，最后给用户。

**核心考点提醒**：
*   **三级映射关系**：`fd` $\rightarrow$ `File` $\rightarrow$ `Inode`。
*   **共享与私有**：
    *   `Inode` 是**共享**的（全系统一份）。
    *   `File` 结构是**会话私有**的（记录自己的偏移量）。
    *   `fd` 是**进程私有**的（自己的小数组）。

### **第 9 页：文件 IO 的幕后英雄 —— `IOParameter`**
*   **核心逻辑**：当进程执行 `read/write` 系统调用时，内核需要一个临时的“记事本”来记录搬运进度。
*   **`u_IOParam` (存在于 `User` 结构中)**：
    *   **`m_Base`**：数据要搬到（或来自）用户空间的哪个内存地址。
    *   **`m_Offset`**：当前读到了文件的第几个字节（逻辑偏移）。
    *   **`m_Count`**：还剩下多少字节没读/没写。
*   **精讲**：每读完一块，内核都会自动更新这三个值：`m_Base` 增加，`m_Offset` 增加，`m_Count` 减少。

### **第 10 页：三级结构的大汇总（必考架构图）**
这张图是文件系统动态运行的**全景图**，请务必能默画出来：
1.  **进程打开文件表**：`fd` 作为下标。
2.  **`File` 结构**：记录“会话”状态（`f_flag`, `f_offset`）。
3.  **内存 Inode**：记录文件的“物理”状态（`i_addr` 地址表）。
*   **逻辑关系**：`fd` $\rightarrow$ `File` $\rightarrow$ `Inode`。
*   **注意**：同一个 Inode 可能会被多个 `File` 结构指向（不同进程打开同一个文件）。

### **第 11-12 页：`read()` 与 `write()` 的语义**
*   **`read(fd, buf, nbytes)`**：
    *   **返回值 $n$**：实际读到的字节数。
    *   **$n < nbytes$**：说明读到文件末尾（EOF）了。
    *   **$n = 0$**：已经到文件尾了，没东西可读。
    *   **副作用**：读完后，`f_offset` 自动加 $n$。
*   **`write(fd, buf, nbytes)`**：
    *   **返回值 $n$**：通常等于 `nbytes`。
    *   **副作用**：文件长度 `i_size` 可能会增加。

### **第 13 页：`read/write` 的内核统一实现 —— `Rdwr()`**
内核为了代码复用，将读和写写在了一个通用的 `Rdwr` 函数里。

**代码填空核心步骤（1-2-3-4-5）：**
1.  **权限检查**：根据 `mode` 检查当前 `File` 是否支持读或写。
2.  **设置 IO 参数**：将用户传进来的参数填入 `u.u_IOParam`。
3.  **读写核心**：
    *   如果是读：调 **`pInode->ReadI()`**。
    *   如果是写：调 **`pInode->WriteI()`**。
4.  **调整指针**：读写完成后，根据实际处理的字节数，更新 `pFile->f_offset`。
5.  **返回结果**：把读到的字节数通过 EAX 返回给用户。

### **第 14-15 页：`ReadI()` 的逻辑全过程（重难点！）**
这是 Inode 级的读操作，它负责把“逻辑文件”变成“物理磁盘块”。

**流程解析：**
1.  **算块号**：
    *   **逻辑块号 `lbn`** = `m_offset / 512`（我要读第几块？）。
    *   **块内偏移 `offset`** = `m_offset % 512`（从这一块的第几个字节开始？）。
2.  **找物理地址 (`Bmap`)**：
    *   调用 **`Bmap()`** 查混合索引表，把逻辑块号 `lbn` 转换成磁盘上的**物理块号 `bn`**。
3.  **调缓存 (`Bread/Breada`)**：
    *   如果需要**预读**（顺序读），调 `Breada`。
    *   否则，调 `Bread` 把物理块 `bn` 读入内核缓存。
4.  **搬数据 (`IOMove`)**：
    *   将缓存块中的数据复制到用户空间的 `m_Base`。
5.  **循环**：
    *   如果用户要读的内容跨越了多个块，循环以上过程。

### **第 16 页：预读逻辑 —— `Breada(bn, rablkno)`**
*   **策略**：为了提速，同步读当前块 `bn` 的同时，**异步**启动对下一块 `rablkno` 的读取。
*   **代码细节**：
    *   对 `bn` 调用 `Strategy` 后会 `IOWait`（同步等待）。
    *   对 `rablkno` 只是发个读请求（`B_ASYNC`），不等待，直接返回。

### **第 17-18 页：预读（Pre-reading）性能深度对比**
这是期末考试最经典的**磁臂移动距离计算题**原型。

*   **场景回顾**：PA 读连续块 $n$ 和 $n+2$，中间杀出一个 PB 去读 10000# 磁道的 $m$。
*   **第 17 页（采用预读）**：
    *   PA 发起 `read(n)` $\rightarrow$ 内核启动同步读 $n$ + **异步预读 $n+2$**。
    *   结果：磁盘队列里同时有了 $[n, n+2]$。紧接着 PB 的 $m$ 进来。
    *   队列顺序：$[n, n+2, m]$。
    *   **磁臂轨迹**：0 $\rightarrow$ 50（处理 $n, n+2$）$\rightarrow$ 10000（处理 $m$）。
    *   **总距离：10000 根磁道。**
*   **第 18 页（不预读）**：
    *   PA 只发 `read(n)`。队列：$[n, m]$。
    *   $n$ 处理完，磁头**必须**去 10000 处理 $m$。
    *   等 $m$ 完事了，PA 运行到下一行代码发 `read(n+2)`。磁头又得从 10000 **跑回** 50。
    *   **总距离：19950 根磁道。**
*   **结论（必考简答）**：预读通过利用**空间局部性**，在多道程序环境下有效**防止了磁头频繁折返**。

---

### **第 19 页：何时放弃预读？（逻辑辨析）**
*   **准则 1**：如果当前块 $bn$ 已经在缓存中了，预读下一块的紧迫性变小。
*   **准则 2（重点）**：如果计算下一块物理地址 $rablkno$ 需要**额外读入索引块**（比如从直接索引跨入间接索引），则预读的开销（多一次索引块 IO）可能抵消其好处，此时内核可能会选择放弃预读。
*   **习题解析（计算 IO 次数）**：
    1.  读偏移 600（1#逻辑块）：**1 次 IO**（直接索引，直接读数据块）。
    2.  读偏移 1000（还是 1#逻辑块）：**0 次 IO**（缓存命中）。
    3.  读逻辑块 6（第一个间接索引）：**2 次 IO**（1次读索引块 $i0$，1次读数据块 $d6$）。

### **第 20 页：`WriteI()` 的逻辑流程（重难点！）**
写操作比读操作复杂，因为它涉及**“分配”**和**“覆盖”**的问题。

*   **Bmap 的副作用**：写文件时，如果逻辑块对应的物理块号 $bn$ 为 0，内核会**当场分配**物理块。
*   **核心分支（必考）：**
    1.  **写满一整块（512字节）**：
        *   调 **`GetBlk(bn)`** 获取缓存块。
        *   **优势**：**不需要先从磁盘读旧内容**，因为整块都会被新数据覆盖。
    2.  **写不满一整块**：
        *   调 **`Bread(bn)`**。
        *   **原因（Read-Before-Write）**：必须把旧数据先读到内存，修改其中的一部分，然后再整体写回，否则没改到的部分会丢失。
*   **收尾**：
    *   写完后，如果是写满一块且是异步，用 `Bawrite`。
    *   如果没写满（常见），用 `Bdwrite`（延迟写），仅在内存打脏标记。

### **第 25 页（PDF 19）：`open` 系统调用的全过程（背诵核心）**
当进程执行 `fd = open(name, mode)` 时，内核按部就班执行以下 6 步：

1.  **`NameI()`**：**路径解析**。把字符串（名字）变成磁盘上的 **Inode 号**。
2.  **`IGet()`**：**节点获取**。根据 Inode 号，把磁盘上的 `DiskInode` 搬到内存里的 `g_InodeTable` 中，并上锁。
3.  **`Access()`**：**权限检查**。看看你当前的用户（UID/GID）有没有权限按 `mode` 打开它。
4.  **分配数据结构**：
    *   在全局 `g_OpenFileTable` 找个空位分配 **`File` 结构**。
    *   在进程自己的 `u_ofiles` 找个最小空位分配 **`fd`**。
5.  **`IPut()`**：**解锁**。活干完了，把 Inode 锁打开（但 Inode 依然留在内存里）。
6.  **返回 fd**：把那个数字（下标）给用户程序。

    *   不以 `/` 开头：从 **当前目录 Inode** (`u_cdir`) 开始。
*   **循环查找**：
    *   把路径拆开，比如 `home`, `John`, `b`。
    *   读取当前目录的数据块 $\rightarrow$ 遍历目录项 $\rightarrow$ 匹配文件名 $\rightarrow$ 得到下一个 Inode 号。

### **第 27-28 页（PDF 21-22）：案例分析 —— 搜索 `/usr/ast/Jerry` 的 IO 次数**

*   **步骤分析**：

    2.  **读根目录数据块**：找 `usr` 的 Inode 号。**1 次 IO**。
    3.  **读 `usr` 的 Inode**：根据 Inode 号读磁盘 Inode 区。**1 次 IO**。
    4.  **读 `usr` 的数据块**：找 `ast` 的 Inode 号。**1 次 IO**。

### **第 29 页（PDF 23）：`IGet()` 函数逻辑 —— 内存 Inode 的管理**

### **第 33 页（PDF 27）：`Unlink()` —— 删除文件**
*   **核心逻辑**：删除文件不是真的把磁盘擦了，而是“断开连接”。
*   **流程**：
    1.  **`NameI()`**：找到文件的 Inode。
    2.  **删除目录项**：在父目录的数据块里，把该文件名对应的 Inode 号改回 **0**。
    3.  **减链接数**：Inode 里的 **`d_nlink - 1`**。
    4.  **真正删除的条件**：只有当 `d_nlink` 变成 **0**，且当前**没有进程正在打开**这个文件时，系统才会释放该文件占用的所有磁盘块和 Inode。

### **第 34 页（PDF 28）：`Close(fd)` —— 会话结束**
*   **三级拆除逻辑（必考）**：
    1.  **进程层**：将进程 `u_ofiles[fd]` 设为 **null**。这个数字（fd）现在自由了，下次 `open` 会优先用它。
    2.  **系统会话层**：`File` 结构的 **`f_count - 1`**。如果减到 0，说明这个会话彻底没人用了，释放 `File` 结构。
    3.  **文件层**：内存 Inode 的 **`i_count - 1`**。如果减到 0，且 Inode 变脏（被改过），则**同步回磁盘**，并从内存表中移除。

---

### **第 35-36 页：标准输入输出 (Standard IO)**
*   **默认配置**：每个进程出生时就带着 3 个打开的文件：
    *   **fd 0**：`STDIN`（标准输入，默认是键盘）。
    *   **fd 1**：`STDOUT`（标准输出，默认是屏幕）。
    *   **fd 2**：`STDERR`（标准错误，Unix V6++ 简化版可能没有）。
*   **考点**：这三个文件**不需要**你自己调 `open`。它们是由父进程（Shell）传给你的，或者在系统初始化时由 `main0` 打开。

---

### **第 37 页：`fork()` 与文件共享（大题必考点！）**
*   **现象**：子进程会**完全继承**父进程的打开文件表。
*   **底层真相**：子进程的 `u_ofiles` 数组是父进程的**拷贝**。
    *   这意味着：父子进程的 fd 指向 **同一个 `File` 结构**。
*   **后果（非常重要）**：
    *   父子进程**共享同一个 `f_offset`（读写指针）**。
    *   如果父进程读了 10 字节，子进程接着读，会从第 11 字节开始，而不是从头开始。

---

### **第 38-41 页：综合习题分析（程序输出题原型）**
这些页展示了多次 `open` 同一个文件的不同情况：
*   **例 2**：`Open("foo")` 得到 fd1=3 $\rightarrow$ `Close(3)` $\rightarrow$ `Open("baz")`。
    *   **结论**：`open` 总是分配**最小的空闲 fd**。所以第二次打开得到的 fd2 依然是 **3**。
*   **例 3**：同一个进程两次 `open("foobar")`。
    *   **结果**：产生 **2 个独立的 `File` 结构**，各自拥有独立的 `f_offset`。
    *   **行为**：`read(fd1)` 读走第 1 个字符，`read(fd2)` 还是会读到第 1 个字符，互不干扰。

---

### **第 42 页：例 4 —— `lseek` 与 `read` 的追踪**
这是一个综合模拟题：
1.  `fd1 = open`, `fd2 = open`。
2.  `read(fd1, &b, 1)`：读出第 0 字节（'a'），`fd1` 的偏移量变成 1。
3.  **`lseek(fd1, 5, 0)`**：将 `fd1` 的偏移量强制改为 **5**。
4.  `read(fd1, &b, 1)`：读出第 5 字节（'f'），偏移量变 6。
5.  `read(fd2, &b, 1)`：因为 `fd2` 是独立会话，其偏移量还是 0，所以读出 **'a'**。

---

### **第 43-44 页：输入输出重定向与 `dup()`**
这是文件系统最神奇的应用：**重定向（Redirection）**。

*   **原理**：程序（如 `ls`）只管往 `fd 1` 写，它不关心 `fd 1` 指向的是屏幕还是文件。
*   **重定向的实现步骤 (Shell 的套路)**：
    1.  `fork()` 一个子进程。
    2.  在子进程中 **`close(1)`**（关闭屏幕输出）。
    3.  **`open("log.txt", ...)`**。
    *   因为 `open` 选最小空闲 fd，而刚才 1 被关了，所以 **fd 1 会指向 log.txt**。
    4.  `exec("ls")`。`ls` 往 1 写，结果就进了文件。
*   **`dup(oldfd)`**：
    *   **功能**：复制一个文件描述符。
    *   **结果**：两个 fd 指向同一个 `File` 结构，**共享偏移量**。

---

### **全章复习最终总结（文件管理·动态）**

1.  **三层结构图**：`fd`（进程私有） $\rightarrow$ `File`（会话私有，存 Offset） $\rightarrow$ `Inode`（全系统共享，存地址表）。
2.  **`fork` 的继承**：父子进程共享 `File` 结构 $\rightarrow$ **共享读写指针**。
3.  **多次 `open`**：产生不同 `File` 结构 $\rightarrow$ **读写指针独立**。
4.  **`dup` 与重定向**：利用“最小 fd 分配原则”来偷梁换柱。
5.  **IO 路径**：`read()` 最终调用 `ReadI()`，利用 `Bmap` 查 `i_addr` 获取物理块，最后调驱动。

**考试叮嘱**：
遇到“求输出结果”的题，先看是 `fork` 出来的还是多次 `open` 出来的。
*   `fork` $\rightarrow$ 指针是一起的。
*   两次 `open` $\rightarrow$ 指针是分开的。
