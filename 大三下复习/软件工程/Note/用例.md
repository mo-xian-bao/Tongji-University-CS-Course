你提到的 **主要参与人（Primary Actor）、次要参与人（Secondary Actor）、基本流程（Main Flow）、替代场景（Alternative Scenarios）**，正是 **用例（Use Case）** 文档的标准组成部分。

用例是结构化分析和 UML 中的核心概念，它比用户故事要**严谨、详细、正式**得多。通常一个用例会写成一个表格或文档片段。

下面是一个标准的 **用例规约（Use Case Specification）** 模板，你可以看到你提到的那些要素都在哪里：

---

### 📝 标准用例模板 (Use Case Template)

#### 1. 基础信息 (Basic Information)
*   **用例名称**：简短动宾短语（例如：取款、提交订单）。
*   **用例 ID**：如 UC-001。
*   **优先级**：高/中/低。

#### 2. 参与者 (Actors) —— **【你要找的】**
*   **主要参与者 (Primary Actor)**：发起这个用例的人（例如：储户）。
*   **次要参与者 (Secondary Actor)**：在过程中配合系统的人或外部系统（例如：银行主机系统、点钞机传感器）。

#### 3. 前置与后置条件 (Preconditions & Postconditions)
*   **前置条件**：开始前必须满足的状态（例如：用户已插入银行卡并校验通过）。
*   **后置条件**：结束后系统的状态（例如：账户余额减少，产生流水记录）。

#### 4. 基本流程 (Basic/Main Flow) —— **【你要找的】**
*   *也叫“快乐路径”（Happy Path），描述一切顺利时的步骤。*
*   1. 储户选择“取款”服务。
*   2. 系统提示输入金额。
*   3. 储户输入 500 元。
*   4. 系统验证余额充足。
*   5. 系统指令点钞机出钞。
*   6. 系统打印凭条并退卡。

#### 5. 扩展流程/替代场景 (Alternative/Exception Flows) —— **【你要找的】**
*   *描述可能发生的意外、错误或分支路径。*
*   **4a. 余额不足**：
    *   4a1. 系统提示“余额不足，请重新输入”。
    *   4a2. 返回步骤 2。
*   **5a. 硬件故障（点钞机卡钞）**：
    *   5a1. 系统提示“硬件故障”。
    *   5a2. 系统冲正交易（恢复余额）。
    *   5a3. 吞卡或提示联系柜台。

### ⚔️ 核心区别：用例 (Use Case) vs 用户故事 (User Story)

既然你之前搞混了，这里有一张对比表帮助你彻底分清它们：

| 特性         | **用户故事 (User Story)**    | **用例 (Use Case)**                            |
| :----------- | :--------------------------- | :--------------------------------------------- |
| **核心理念** | **对话** (Conversation)      | **文档** (Documentation)                       |
| **详细程度** | 简略，只写意图，细节靠聊     | **详尽**，覆盖所有步骤和分支                   |
| **侧重点**   | 关注**价值** (Value)         | 关注**功能实现逻辑** (Logic)                   |
| **流程描述** | 几乎不写，或写在验收标准里   | **核心内容**，通过基本流/扩展流详细描述        |
| **谁来写？** | 产品负责人 (PO) + 团队共创   | 需求分析师 (BA) 或 系统架构师                  |
| **适用场景** | 敏捷开发，需求变化快         | 瀑布模型，或高风险、复杂的系统（如银行、医疗） |
| **你的问题** | 参与人、流程通常是**隐含**的 | 参与人、流程是**显式定义**的                   |

### 总结
*   如果你在写 **“As a... I want...”**，那是**用户故事**，重点是“我要什么价值”。
*   如果你在写 **“Step 1, Step 2, Exception 3a...”**，那是**用例**，重点是“系统具体怎么运行”。

所以，你需要写的那些“主要/次要参与人、主流程、异常流程”，**确实是写在用例规约里的**。
