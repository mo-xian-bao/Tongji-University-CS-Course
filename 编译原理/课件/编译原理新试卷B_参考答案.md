## 三、DFA 构造与最小化

正规式 `(0|1)*01` 表示所有以 `01` 结尾的二进制串。构造 `DFA` 时，只需要记录当前输入串末尾与模式 `01` 的最长匹配后缀。

构造状态：

- `q0`：当前没有匹配到有用后缀。
- `q1`：当前最长有用后缀为 `0`。
- `q2`：当前最长有用后缀为 `01`，是接受状态。

转移分析：

- 在 `q0` 读入 `0`，得到后缀 `0`，转到 `q1`；读入 `1`，仍没有有用后缀，留在 `q0`。
- 在 `q1` 读入 `0`，最长有用后缀仍是 `0`，留在 `q1`；读入 `1`，得到后缀 `01`，转到 `q2`。
- 在 `q2` 读入 `0`，新的最长有用后缀为 `0`，转到 `q1`；读入 `1`，不再以 `0` 或 `01` 结尾，转到 `q0`。

转移表：

| 状态 | 0 | 1 |
| ---- | - | - |
| `q0` | `q1` | `q0` |
| `q1` | `q1` | `q2` |
| `q2` | `q1` | `q0` |

初态：`q0`。终态：`q2`。

最小化过程：

1. 初始划分为终态和非终态：`{q2}`、`{q0,q1}`。
2. 比较 `q0` 和 `q1`：输入 `1` 时，`q0` 到非终态集合，`q1` 到终态集合，因此二者可区分。
3. 最终划分为 `{q0}`、`{q1}`、`{q2}`，没有状态可合并。

所以该 `DFA` 已经是最小 `DFA`。

## 四、文法分析题

原文法：

```text
S → c | Λ | {T}
T → T:S | S
```

### 1. 消去左递归

`S` 没有左递归。`T` 有直接左递归：

```text
T → T:S | S
```

套用公式：

```text
A → Aα | β
```

可改写为：

```text
A  → βA'
A' → αA' | ε
```

因此：

```text
S  → c | Λ | {T}
T  → S T'
T' → : S T' | ε
```

### 2. 判断是否为 LL(1)

为避免和集合符号混淆，下面把 `{` 写作“左花括号”，把 `}` 写作“右花括号”。

计算 `FIRST` 集：

```text
FIRST(S)  = { c, Λ, 左花括号 }
FIRST(T)  = FIRST(S) = { c, Λ, 左花括号 }
FIRST(T') = { :, ε }
```

计算关键 `FOLLOW` 集：

- `T` 出现在 `S → {T}` 中，所以右花括号属于 `FOLLOW(T)`。
- `T'` 出现在 `T → S T'` 末尾，所以 `FOLLOW(T') = FOLLOW(T)`。

因此：

```text
FOLLOW(T)  = { 右花括号 }
FOLLOW(T') = { 右花括号 }
```

检查预测分析表是否冲突：

- `S → c`、`S → Λ`、`S → {T}` 的可选首符号分别是 `c`、`Λ`、左花括号，互不相交。
- `T' → :ST'` 的 `FIRST` 集为 `{ : }`。
- `T' → ε` 填入 `FOLLOW(T')`，即右花括号列。
- 冒号和右花括号不同，因此无冲突。

所以改写后的文法是 `LL(1)` 文法。

### 3. 预测分析表

|      | c | Λ | { | } | : | # |
| ---- | - | - | - | - | - | - |
| S    | `S→c` | `S→Λ` | `S→{T}` |   |   |   |
| T    | `T→ST'` | `T→ST'` | `T→ST'` |   |   |   |
| T'   |   |   |   | `T'→ε` | `T'→:ST'` |   |

### 4. 输入串 `{c:Λ}#` 的预测分析过程

约定分析栈左端为栈底、右端为栈顶。

| 步骤 | 分析栈 | 剩余输入串 | 动作 |
| ---- | ------ | ---------- | ---- |
| 1 | `# S` | `{ c : Λ } #` | 用 `S→{T}` |
| 2 | `# } T {` | `{ c : Λ } #` | 匹配 `{` |
| 3 | `# } T` | `c : Λ } #` | 用 `T→ST'` |
| 4 | `# } T' S` | `c : Λ } #` | 用 `S→c` |
| 5 | `# } T' c` | `c : Λ } #` | 匹配 `c` |
| 6 | `# } T'` | `: Λ } #` | 用 `T'→:ST'` |
| 7 | `# } T' S :` | `: Λ } #` | 匹配 `:` |
| 8 | `# } T' S` | `Λ } #` | 用 `S→Λ` |
| 9 | `# } T' Λ` | `Λ } #` | 匹配 `Λ` |
| 10 | `# } T'` | `} #` | 用 `T'→ε` |
| 11 | `# }` | `} #` | 匹配 `}` |
| 12 | `#` | `#` | 接受 |

分析成功，说明 `{c:Λ}` 是该文法的句子。

## 五、循环优化题

原程序：

```text
P := 0
N := 1
L1: Q := R - 5
    H := Q * N
    P := P + H
    If N = 64 goto L2
    N := N + 1
    goto L1
L2:
```

### 1. 划分基本块

基本块入口包括：程序第一条语句、标号语句、跳转目标语句、条件或无条件跳转之后的语句。

划分为：

```text
B1:
    P := 0
    N := 1

B2:
L1: Q := R - 5
    H := Q * N
    P := P + H
    If N = 64 goto L2

B3:
    N := N + 1
    goto L1

B4:
L2:
```

### 2. 控制流图

```text
B1 → B2
B2 → B4    条件为真，跳出循环
B2 → B3    条件为假，继续循环
B3 → B2    回到循环入口
```

循环体由 `B2、B3` 构成，`B1` 是循环前置区域，`B4` 是循环出口。

### 3. 循环优化

在循环中：

```text
Q := R - 5
```

若 `R` 在循环体中不被修改，则 `R - 5` 每次迭代结果相同，是循环不变式，可外提到循环前置块。

优化后：

```text
B1:
    P := 0
    N := 1
    Q := R - 5

B2:
L1: H := Q * N
    P := P + H
    If N = 64 goto L2

B3:
    N := N + 1
    goto L1

B4:
L2:
```

优化后的控制流图仍为：

```text
B1 → B2
B2 → B4
B2 → B3
B3 → B2
```

变化在于循环中少计算了一次循环不变表达式 `R - 5`。

## 六、目标代码生成题

中间代码：

```text
1. T := M - N
2. U := P + Q
3. V := T + U
4. W := V - T
5. Z := W + U
```

出口活跃变量：`W、Z`。

### 1. 待用与活跃信息

从基本块末尾向前扫描。出口处 `W、Z` 活跃，其他临时变量若之后不再使用则不活跃。

| 语句 | 语句执行前的主要待用/活跃信息 | 说明 |
| ---- | ---------------------------- | ---- |
| `T := M - N` | `M(1,活)`, `N(1,活)`, `P(2,活)`, `Q(2,活)` | `M、N` 当前语句使用；`P、Q` 下一条使用 |
| `U := P + Q` | `P(2,活)`, `Q(2,活)`, `T(3,活)` | `T` 在第 3 条还要使用 |
| `V := T + U` | `T(3,活)`, `U(3,活)` | `T` 还会在第 4 条使用；`U` 还会在第 5 条使用 |
| `W := V - T` | `V(4,活)`, `T(4,活)`, `U(5,活)` | `W` 生成后在第 5 条使用，且出口活跃 |
| `Z := W + U` | `W(5,活)`, `U(5,活)` | 生成 `Z`，且 `W、Z` 出口活跃 |

执行完第 5 条后，`W、Z` 在基本块出口活跃，因此需要保存。

### 2. 目标代码

一种可行的目标代码如下：

```text
LD  R0, M
SUB R0, N        ; R0 = T
ST  T, R0        ; T 后面还要用，保存

LD  R1, P
ADD R1, Q        ; R1 = U
ST  U, R1        ; U 后面还要用，保存

ADD R0, R1       ; R0 = V
LD  R1, T
SUB R0, R1       ; R0 = W
ST  W, R0        ; W 是出口活跃变量，保存

LD  R1, U
ADD R0, R1       ; R0 = Z
ST  Z, R0        ; Z 是出口活跃变量，保存
```

说明：目标代码不唯一，只要寄存器分配合理，并在必要时保存出口活跃变量即可。

1. `while` 条件 `m<=n`：

3. `then` 和 `else` 执行完后都跳回 `while` 条件开始处。

## 八、LR(0) 分析题

文法：

```text
E → F + F | F - F
F → x | y
```

拓广文法编号：

```text
0. E' → E
1. E  → F + F
2. E  → F - F
3. F  → x
4. F  → y
```

### 1. 所有 LR(0) 项目

对每个产生式，在右部所有可能位置加圆点：

```text
E' → ·E
E' → E·

E → ·F+F
E → F·+F
E → F+·F
E → F+F·

E → ·F-F
E → F·-F
E → F-·F
E → F-F·

F → ·x
F → x·
F → ·y
F → y·
```

### 2. 项目集规范族与 DFA

```text
I0:
  E' → ·E
  E  → ·F+F
  E  → ·F-F
  F  → ·x
  F  → ·y

I1:
  E' → E·

I2:
  E → F·+F
  E → F·-F

I3:
  F → x·

I4:
  F → y·

I5:
  E → F+·F
  F → ·x
  F → ·y

I6:
  E → F-·F
  F → ·x
  F → ·y

I7:
  E → F+F·

I8:
  E → F-F·
```

DFA 转换：

```text
I0 --E--> I1
I0 --F--> I2
I0 --x--> I3
I0 --y--> I4
I2 --"+"--> I5
I2 --"-"--> I6
I5 --F--> I7
I5 --x--> I3
I5 --y--> I4
I6 --F--> I8
I6 --x--> I3
I6 --y--> I4
```

### 3. LR(0) 分析表

规约编号：

```text
r1: E → F+F
r2: E → F-F
r3: F → x
r4: F → y
```

| 状态 | + | - | x | y | # | E | F |
| ---- | - | - | - | - | - | - | - |
| 0 |   |   | `s3` | `s4` |   | 1 | 2 |
| 1 |   |   |   |   | `acc` |   |   |
| 2 | `s5` | `s6` |   |   |   |   |   |
| 3 | `r3` | `r3` | `r3` | `r3` | `r3` |   |   |
| 4 | `r4` | `r4` | `r4` | `r4` | `r4` |   |   |
| 5 |   |   | `s3` | `s4` |   |   | 7 |
| 6 |   |   | `s3` | `s4` |   |   | 8 |
| 7 | `r1` | `r1` | `r1` | `r1` | `r1` |   |   |
| 8 | `r2` | `r2` | `r2` | `r2` | `r2` |   |   |

### 4. 是否为 LR(0) 文法

是 `LR(0)` 文法。

理由：分析表中没有同一入口既有移进又有规约，也没有同一入口出现两个不同规约，因此不存在移进-规约冲突和规约-规约冲突。

### 5. 输入串 `x+y#` 的 LR(0) 分析过程

使用上面的分析表。约定栈中交替记录状态和文法符号，初始栈为 `0`。

| 步骤 | 分析栈 | 剩余输入串 | 动作 |
| ---- | ------ | ---------- | ---- |
| 1 | `0` | `x + y #` | `ACTION[0,x]=s3`，移进 `x` |
| 2 | `0 x 3` | `+ y #` | `ACTION[3,+]=r3`，按 `F→x` 规约 |
| 3 | `0 F 2` | `+ y #` | `ACTION[2,+]=s5`，移进 `+` |
| 4 | `0 F 2 + 5` | `y #` | `ACTION[5,y]=s4`，移进 `y` |
| 5 | `0 F 2 + 5 y 4` | `#` | `ACTION[4,#]=r4`，按 `F→y` 规约 |
| 6 | `0 F 2 + 5 F 7` | `#` | `ACTION[7,#]=r1`，按 `E→F+F` 规约 |
| 7 | `0 E 1` | `#` | `ACTION[1,#]=acc`，接受 |

因此输入串 `x+y#` 可被该 `LR(0)` 分析表接受。

## 九、运行时存储空间组织题

过程静态层次：

```text
M: 0
A: 1    C: 1
B: 2
```

调用序列为：

```text
M → C → A → B1 → B2
```

其中 `B1` 表示第一次 `B` 的活动，`B2` 表示第二次递归调用产生的最新 `B` 活动。

### 1. 运行栈中的活动记录次序

从栈底到栈顶：

```text
AR(M), AR(C), AR(A), AR(B1), AR(B2)
```

解释：运行栈按动态调用次序保存活动记录。递归调用时，同一个过程 `B` 可以同时有多个活动记录。

### 2. 动态链和静态链

动态链指向调用本过程前的最新活动记录，即调用者活动记录。静态链指向本过程静态直接外层过程的最新活动记录。

| 活动记录 | 动态链指向 | 静态链指向 | 说明 |
| -------- | ---------- | ---------- | ---- |
| `AR(M)` | 空 | 空 | 主程序无调用者，也无静态外层 |
| `AR(C)` | `AR(M)` | `AR(M)` | `C` 由 `M` 调用，且定义在 `M` 内 |
| `AR(A)` | `AR(C)` | `AR(M)` | `A` 由 `C` 调用，但静态外层是 `M` |
| `AR(B1)` | `AR(A)` | `AR(A)` | `B` 定义在 `A` 内，第一次由 `A` 调用 |
| `AR(B2)` | `AR(B1)` | `AR(A)` | 第二次 `B` 由 `B1` 调用，但静态外层仍是 `A` |

关键区别：`B2` 的动态链指向 `B1`，静态链指向 `A`。递归调用不会使 `B1` 成为 `B2` 的静态外层。

### 3. 执行点 Y 处 DISPLAY 表

`DISPLAY[k]` 保存当前可见的第 `k` 层最新活动记录地址。执行点在第二次递归调用的 `B2` 中，`B` 的静态外层链为 `B → A → M`。

| 层次 | DISPLAY 内容 |
| ---- | ------------ |
| 0 | `AR(M)` |
| 1 | `AR(A)` |
| 2 | `AR(B2)` |

注意：`AR(C)` 和 `AR(B1)` 都不在当前 `DISPLAY` 表中。`C` 只是动态调用链上的过程，不是 `B` 的静态外层；`B1` 是同一过程的前一个递归活动，不是 `B2` 的外层过程。

### 4. 变量访问

| 变量 | 定义位置 | 层次 | 在 `B2` 中是否可按词法作用域访问 | DISPLAY 访问 |
| ---- | -------- | ---- | -------------------------------- | ------------ |
| `g` | `M` | 0 | 可以 | 通过 `DISPLAY[0]` |
| `a` | `A` | 1 | 可以 | 通过 `DISPLAY[1]` |
| `b` | 当前 `B2` | 2 | 可以 | 通过 `DISPLAY[2]` 或当前活动记录 |
| `c` | `C` | 1 | 不可以 | 不能通过 `B2` 的 DISPLAY 直接访问 |

原因：静态作用域只允许访问本过程及其静态外层过程中的名字。`C` 是调用链上的过程，但不是 `B` 的静态外层，因此 `B2` 不能直接访问 `C` 的局部变量 `c`。
