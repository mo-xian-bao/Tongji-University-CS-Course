## 二、实验的总体结构

### 2.1 五级流水线结构

本设计采用经典的**五级流水线架构**，将指令执行过程分解为五个独立的阶段，每个阶段在一个时钟周期内完成特定功能。流水线各阶段之间通过**流水线寄存器**进行数据传递和同步。

#### 流水线结构示意图
```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│   IF    │ => │   ID    │ => │   EX    │ => │   MEM   │ => │   WB    │
│ 取指令  │    │ 译码    │    │ 执行    │    │ 访存    │    │ 写回    │
└─────────┘    └─────────┘    └─────────┘    └─────────┘    └─────────┘
     ↓              ↓              ↓              ↓              ↓
   IF/ID          ID/EX          EX/MEM        MEM/WB         (寄存器)
  流水线寄存器    流水线寄存器    流水线寄存器   流水线寄存器
```

#### 2.1.1 IF阶段（Instruction Fetch - 取指令）

**主要功能**：
- 根据PC值从指令存储器（IMEM）中取出指令
- 计算下一条指令地址（PC+4）
- 处理分支/跳转时的PC重定向

**涉及信号**：
```verilog
reg [31:0] PC;              // 程序计数器
wire [31:0] IF_instr;       // 取出的指令
wire [31:0] PC_plus_4;      // PC + 4
```

**工作流程**：
1. 将当前PC值送入IMEM
2. IMEM返回32位指令
3. 计算PC+4作为顺序执行的下一个地址
4. 根据控制信号选择下一个PC值（顺序/分支/跳转）

**特殊说明**：采用**哈佛结构**，指令存储器(IMEM)和数据存储器(DMEM)物理分离，允许同时访问指令和数据，提高流水线效率。

#### 2.1.2 ID阶段（Instruction Decode - 指令译码）

**主要功能**：
- 解析指令各字段（opcode, rs, rt, rd, imm等）
- 从寄存器文件读取源操作数
- 生成控制信号
- 进行立即数符号扩展
- 实施数据转发（用于分支判断）

**涉及信号**：
```verilog
wire [5:0] ID_opcode;       // 操作码
wire [4:0] ID_rs, ID_rt, ID_rd;  // 寄存器地址
wire [31:0] ID_rs_data, ID_rt_data;  // 寄存器数据
wire ID_reg_write, ID_mem_read;      // 控制信号
wire [3:0] ID_alu_op;                // ALU操作码
```

**工作流程**：
1. 指令字段拆分（位切片）
2. 根据opcode生成所有控制信号
3. 从RegFile读取rs和rt寄存器的值
4. 立即数进行16位到32位的符号扩展
5. 确定写回的目标寄存器（rd或rt）
6. 数据转发逻辑处理（解决分支指令的数据冒险）

#### 2.1.3 EX阶段（Execute - 执行）

**主要功能**：
- ALU执行算术/逻辑运算
- 计算访存地址
- 处理数据转发（来自EX/MEM和MEM/WB）
- 产生标志位（零标志、负标志等）

**涉及信号**：
```verilog
wire [31:0] EX_alu_input_a, EX_alu_input_b;  // ALU输入
wire [31:0] EX_alu_result;                   // ALU输出
wire EX_zero, EX_negative;                   // 标志位
wire [1:0] EX_forward_a, EX_forward_b;       // 转发控制
```

**工作流程**：
1. 根据转发信号选择ALU的操作数来源：
   - 00: 来自ID/EX寄存器（无转发）
   - 01: 来自MEM/WB（WB阶段转发）
   - 10: 来自EX/MEM（MEM阶段转发）
2. 根据alu_src选择第二操作数（寄存器/立即数）
3. ALU执行相应运算（支持13种操作）
4. 产生并传递标志位

#### 2.1.4 MEM阶段（Memory Access - 访存）

**主要功能**：
- 执行Load指令（从DMEM读数据）
- 执行Store指令（向DMEM写数据）
- 传递ALU结果（非访存指令）

**涉及信号**：
```verilog
wire [31:0] MEM_read_data;      // 从内存读取的数据
reg EX_MEM_mem_read;            // 读使能
reg EX_MEM_mem_write;           // 写使能
reg [31:0] EX_MEM_alu_result;   // 访存地址
```

**工作流程**：
1. 将ALU结果作为访存地址
2. 根据mem_read信号从DMEM读数据
3. 根据mem_write信号向DMEM写数据
4. 传递ALU结果和内存数据到下一阶段

#### 2.1.5 WB阶段（Write Back - 写回）

**主要功能**：
- 选择写回数据（ALU结果或内存数据）
- 将数据写回寄存器文件

**涉及信号**：
```verilog
wire [31:0] WB_write_data;      // 写回数据
reg [4:0] MEM_WB_write_reg;     // 目标寄存器
reg MEM_WB_reg_write;           // 写使能
```

**工作流程**：
1. 根据mem_read信号选择数据来源（MEM/ALU）
2. 如果reg_write=1，将数据写入目标寄存器
3. 提供数据转发路径给EX阶段

#### 2.1.6 流水线寄存器详细说明

流水线寄存器在时钟上升沿将数据从一个阶段传递到下一个阶段，实现流水线的并行执行。

##### IF/ID流水线寄存器
```verilog
reg [31:0] IF_ID_PC;        // PC值（用于分支地址计算）
reg [31:0] IF_ID_instr;     // 指令本身
```
**更新条件**：
- 复位时清零
- flush_IF_ID=1时清空（分支跳转）
- stall=1时保持（流水线暂停）
- 正常时钟上升沿更新

##### ID/EX流水线寄存器
```verilog
// 数据通路
reg [31:0] ID_EX_rs_data;       // 源寄存器1数据
reg [31:0] ID_EX_rt_data;       // 源寄存器2数据
reg [31:0] ID_EX_imm_ext;       // 符号扩展立即数

// 寄存器地址
reg [4:0] ID_EX_rs, ID_EX_rt, ID_EX_rd;
reg [4:0] ID_EX_write_reg;      // 目标寄存器

// 控制信号
reg ID_EX_reg_write;            // 寄存器写使能
reg ID_EX_mem_read;             // 内存读使能
reg ID_EX_mem_write;            // 内存写使能
reg [3:0] ID_EX_alu_op;         // ALU操作码
```
**更新条件**：
- 复位时清零
- flush_ID_EX=1时清空控制信号（插入气泡）
- stall=1时保持（关键修复：必须保持，不能清零）
- 正常时使用ID阶段未转发的数据（ID_rs_data, ID_rt_data）

##### EX/MEM流水线寄存器
```verilog
reg [31:0] EX_MEM_alu_result;   // ALU运算结果
reg [31:0] EX_MEM_rt_data;      // rt数据（用于store）
reg [4:0] EX_MEM_write_reg;     // 目标寄存器
reg EX_MEM_reg_write;           // 寄存器写使能
reg EX_MEM_mem_read;            // 内存读使能
reg EX_MEM_mem_write;           // 内存写使能
```
**更新条件**：
- 仅在复位时清零
- 正常时钟上升沿更新（不受stall/flush影响）

##### MEM/WB流水线寄存器
```verilog
reg [31:0] MEM_WB_alu_result;   // ALU结果
reg [31:0] MEM_WB_mem_data;     // 内存读取数据
reg [4:0] MEM_WB_write_reg;     // 目标寄存器
reg MEM_WB_reg_write;           // 寄存器写使能
reg MEM_WB_mem_read;            // 内存读使能标志
```
**更新条件**：
- 仅在复位时清零
- 正常时钟上升沿更新（不受stall/flush影响）

### 2.2 数据转发、暂停和清空控制机制

为了解决流水线中的**数据冒险**和**控制冒险**，本设计实现了专门的**Hazard_Unit（冒险检测单元）**，负责检测冒险并生成相应的控制信号。

#### 2.2.1 数据冒险类型与解决方案

##### (1) RAW冒险（Read After Write）

**问题描述**：后续指令需要读取前面指令还未写回的寄存器。

**示例**：
```assembly
ADD $3, $1, $2    # 指令1: $3 = $1 + $2
SUB $5, $3, $4    # 指令2: 需要读取$3（还在流水线中）
```

**时序分析**：
```
时钟周期:  1    2    3    4    5    6
ADD:      IF   ID   EX   MEM  WB
SUB:           IF   ID   EX   MEM  WB
                   ↑需要$3
                   数据在EX/MEM寄存器中
```

**解决方案：数据转发（Forwarding）**

实现了两条转发路径：

**① EX/MEM → EX 转发**（MEM阶段到EX阶段）
```verilog
// Hazard_Unit.v 中的转发逻辑
if (EX_MEM_reg_write && 
    (EX_MEM_write_reg != 5'b00000) && 
    (EX_MEM_write_reg == ID_EX_rs)) begin
    EX_forward_a = 2'b10;  // 从EX/MEM转发到ALU输入A
end
```

**② MEM/WB → EX 转发**（WB阶段到EX阶段）
```verilog
if (MEM_WB_reg_write && 
    (MEM_WB_write_reg != 5'b00000) && 
    (MEM_WB_write_reg == ID_EX_rs)) begin
    EX_forward_a = 2'b01;  // 从MEM/WB转发到ALU输入A
end
```

**转发优先级**：EX/MEM优先于MEM/WB（因为EX/MEM的数据更新）

##### (2) Load-Use冒险

**问题描述**：Load指令后紧跟使用该数据的指令。

**示例**：
```assembly
LOAD $3, 0($1)    # 指令1: 从内存加载到$3
ADD  $5, $3, $4   # 指令2: 立即使用$3
```

**时序分析**：
```
时钟周期:  1    2    3    4    5    6
LOAD:     IF   ID   EX   MEM  WB
ADD:           IF   ID   EX   MEM  WB
                   ↑需要$3
                   但数据要到MEM阶段才能读出！
```

**问题核心**：即使采用转发，数据也要到MEM阶段结束才可用，而ADD在EX阶段就需要数据。

**解决方案：流水线暂停（Stall）**
```verilog
// 检测Load-Use冒险
assign load_use_hazard = ID_EX_mem_read && 
                         ((ID_EX_write_reg == ID_rs) || 
                          (ID_EX_write_reg == ID_rt)) &&
                         (ID_EX_write_reg != 5'b00000);

// 产生stall信号
if (load_use_hazard) begin
    stall = 1'b1;
    flush_ID_EX = 1'b1;  // 在ID/EX插入气泡（bubble/NOP）
end
```

**效果**：
```
原始时序:  1    2    3    4    5    6
LOAD:     IF   ID   EX   MEM  WB
ADD:           IF   ID   EX   MEM  WB  ← 错误！

修正后:    1    2    3    4    5    6    7
LOAD:     IF   ID   EX   MEM  WB
ADD:           IF   ID   [气泡] EX   MEM  WB  ← 正确！
                      ↑stall一周期
```

##### (3) 分支数据冒险（关键修复点）

**问题描述**：分支指令需要的数据还在流水线中。

**示例**：
```assembly
ADD  $t0, $s2, $s3    # $t0 = low + high
ADDI $t0, $t0, 1      # $t0 = low + high + 1
SRA  $t0, $t0, 1      # $t0 = mid (算术右移)
BN   $s4, $t0, LABEL  # 需要读取$t0进行比较
```

**时序问题**：
```
时钟周期:  N    N+1  N+2  N+3  N+4  N+5
SRA:      IF   ID   EX   MEM  WB
BN:            IF   ID   EX   MEM  WB
                   ↑需要$t0
```

**问题分析**：
- 虽然有从EX/MEM到ID的转发通路
- 但转发的是`EX_MEM_alu_result`**寄存器**中的值
- 当SRA在EX阶段时，`EX_MEM_alu_result`还保存着**上一条指令的结果**
- 只有在下一个时钟上升沿，SRA的结果才会锁存到`EX_MEM_alu_result`

**解决方案：扩展分支暂停检测**
```verilog
// 检测分支指令是否需要等待前面指令写回
assign branch_stall = ID_branch && (
    // 检查ID/EX阶段冲突
    (ID_EX_reg_write && (ID_EX_write_reg != 5'b00000) &&
     ((ID_EX_write_reg == ID_rs) || (ID_EX_write_reg == ID_rt))) ||
    // 【关键】检查EX/MEM阶段冲突
    (EX_MEM_reg_write && (EX_MEM_write_reg != 5'b00000) &&
     ((EX_MEM_write_reg == ID_rs) || (EX_MEM_write_reg == ID_rt)))
);
```

**为什么需要检查EX/MEM**：
- 即使有转发通路，也只能转发**已经锁存在寄存器中的数据**
- 当指令刚进入EX阶段时，结果还在ALU的组合逻辑中计算
- 必须等待一个时钟周期，让结果锁存到EX/MEM寄存器
- 然后才能通过转发路径正确地传递到ID阶段

#### 2.2.2 控制冒险与解决方案

##### (1) 分支/跳转冒险

**问题描述**：分支或跳转指令会改变PC，但后续指令已经进入流水线。

**示例**：
```assembly
BN   $1, $2, LABEL   # 如果$1 < $2则跳转
ADD  $3, $4, $5      # 可能不应该执行
SUB  $6, $7, $8      # 可能不应该执行
```

**解决方案：流水线清空（Flush）**
```verilog
// 在分支跳转时清空IF/ID和ID/EX
if (branch_taken || jump) begin
    flush_IF_ID = 1'b1;  // 清空IF/ID（取消已取指令）
    flush_ID_EX = 1'b1;  // 清空ID/EX（取消已译码指令）
end
```

**关键修复：分支判断考虑暂停状态**
```verilog
// PCPU.v 中的分支判断逻辑
assign branch_taken = !stall && (  // 【关键】只有在非暂停时才跳转
    (ID_opcode == OP_BZ && (ID_rs_data_fwd == ID_rt_data_fwd)) ||
    (ID_opcode == OP_BN && ($signed(ID_rs_data_fwd) < $signed(ID_rt_data_fwd)))
);
```

**为什么需要`!stall`**：
- 如果检测到数据冒险需要stall
- 但没有禁止branch_taken
- 分支会使用**错误的数据**进行判断并跳转
- 加上`!stall`后，暂停期间分支不会执行，等数据准备好后再判断

#### 2.2.3 流水线控制信号总结

##### stall信号（流水线暂停）
```verilog
stall = load_use_hazard || branch_stall;
```

**效果**：
- PC保持不变
- IF/ID寄存器保持不变
- ID/EX插入气泡（NOP）

##### flush信号（流水线清空）
```verilog
// flush_IF_ID: 清空IF/ID寄存器
if (branch_taken || jump) flush_IF_ID = 1;

// flush_ID_EX: 清空ID/EX寄存器的控制信号
if (branch_taken || jump) flush_ID_EX = 1;
else if (stall) flush_ID_EX = 1;  // stall时插入气泡
```

**清空方式**：
- 将控制信号设置为0（reg_write=0, mem_write=0等）
- 数据通路的值不重要（因为不会被使用）

##### forward信号（数据转发）
```verilog
forward_a[1:0]:
  00 = 无转发，使用ID/EX寄存器中的数据
  01 = 从MEM/WB转发
  10 = 从EX/MEM转发

forward_b[1:0]: 同forward_a
```

#### 2.2.4 冒险处理流程图
```
[指令进入ID阶段]
        |
        v
[检查是否为Load指令后续指令] --是--> [stall=1, flush_ID_EX=1]
        |否                             |
        v                               v
[检查是否为分支且有数据冒险] --是--> [stall=1, flush_ID_EX=1]
        |否                             |
        v                               v
[检查是否需要数据转发] --是--> [设置forward信号]
        |否                             |
        v                               v
[正常执行]                        [等待一周期]
```

### 2.3 16条指令的选取与指令格式设计

#### 2.3.1 指令选取原则

本设计选取的16条指令遵循以下原则：

1. **完备性**：覆盖基本的计算机指令类别
   - 算术运算（加、减）
   - 逻辑运算（与、或、异或）
   - 移位操作（逻辑/算术左移右移）
   - 访存操作（加载、存储）
   - 控制转移（分支、跳转）
   - 系统控制（停机、空操作）

2. **实用性**：支持常见算法实现
   - 循环结构（分支指令）
   - 数组访问（加载/存储 + 立即数偏移）
   - 条件判断（比较 + 分支）
   - 位操作（移位、逻辑运算）

3. **简洁性**：控制硬件复杂度
   - 统一的32位指令格式
   - 三种基本格式（R型、I型、J型）
   - 简化的操作码编码

#### 2.3.2 指令分类与功能

##### (1) 算术运算指令（3条）

| 指令 | 操作码 | 格式 | 功能                  | 用途               |
| ---- | ------ | ---- | --------------------- | ------------------ |
| ADD  | 0x02   | R    | rd = rs + rt (有符号) | 整数加法           |
| SUB  | 0x03   | R    | rd = rs - rt (有符号) | 整数减法、比较     |
| ADDI | 0x0D   | I    | rt = rs + imm         | 加立即数、地址计算 |

**设计说明**：
- 仅支持有符号运算（简化ALU设计）
- ADDI覆盖了加载常数、地址计算等常见需求
- 可通过SUB实现比较操作

##### (2) 逻辑运算指令（3条）

| 指令 | 操作码 | 格式 | 功能          | 用途             |
| ---- | ------ | ---- | ------------- | ---------------- |
| AND  | 0x04   | R    | rd = rs & rt  | 位掩码、条件判断 |
| OR   | 0x05   | R    | rd = rs \| rt | 位组合           |
| XOR  | 0x06   | R    | rd = rs ^ rt  | 位翻转、比较     |

**设计说明**：
- 支持按位操作
- 可实现简单的密码运算
- XOR可用于快速零值检测（x ^ x = 0）

##### (3) 移位运算指令（3条）

| 指令 | 操作码 | 格式 | 功能                    | 用途            |
| ---- | ------ | ---- | ----------------------- | --------------- |
| SLL  | 0x07   | R    | rd = rt << shamt        | 乘以2的幂       |
| SRL  | 0x08   | R    | rd = rt >> shamt (逻辑) | 无符号除以2的幂 |
| SRA  | 0x09   | R    | rd = rt >> shamt (算术) | 有符号除以2的幂 |

**设计说明**：
- shamt字段支持0-31位移位
- SRL用于无符号数，高位补0
- SRA用于有符号数，高位补符号位
- 可快速实现乘除法（2的幂次）

##### (4) 访存指令（2条）

| 指令  | 操作码 | 格式 | 功能               | 用途         |
| ----- | ------ | ---- | ------------------ | ------------ |
| LOAD  | 0x0B   | I    | rd = MEM[rs + imm] | 从内存读数据 |
| STORE | 0x0C   | I    | MEM[rs + imm] = rt | 向内存写数据 |

**设计说明**：
- 支持基址+偏移寻址
- 偏移量为16位有符号立即数（-32768到+32767）
- 字（32位）对齐访问
- 实现哈佛结构（指令和数据分离）

##### (5) 分支指令（2条）

| 指令 | 操作码 | 格式 | 功能                       | 用途               |
| ---- | ------ | ---- | -------------------------- | ------------------ |
| BZ   | 0x0E   | I    | if (rs == rt) PC += offset | 相等则跳转         |
| BN   | 0x0F   | I    | if (rs < rt) PC += offset  | 小于则跳转(有符号) |

**设计说明**：
- PC相对寻址（offset左移2位，按字对齐）
- 支持向前和向后跳转
- 可实现条件分支和循环
- 在ID阶段判断和跳转（早期分支）

##### (6) 跳转指令（1条）

| 指令 | 操作码 | 格式 | 功能      | 用途       |
| ---- | ------ | ---- | --------- | ---------- |
| JMP  | 0x10   | J    | PC = addr | 无条件跳转 |

**设计说明**：
- 伪直接寻址（26位地址 + PC高4位）
- 覆盖256MB地址空间
- 用于函数调用、远跳转

##### (7) 特殊指令（3条）

| 指令 | 操作码 | 格式 | 功能                 | 用途         |
| ---- | ------ | ---- | -------------------- | ------------ |
| NOP  | 0x00   | R    | 无操作               | 占位、延时   |
| HALT | 0x01   | R    | 停机                 | 程序结束     |
| CMP  | 0x0A   | R    | 比较rs和rt，设标志位 | 辅助比较操作 |

**设计说明**：
- NOP可用于流水线调试
- HALT设置halt寄存器，停止取指
- CMP产生标志位，配合分支使用

#### 2.3.3 指令格式设计

本设计采用**定长指令编码**，所有指令均为**32位**，根据指令类型分为三种格式：

##### R型指令（Register类型）

**格式布局**：
```
 31    26 25   21 20   16 15   11 10    6 5     0
┌────────┬────────┬────────┬────────┬────────┬────────┐
│ opcode │   rs   │   rt   │   rd   │ shamt  │ 保留   │
└────────┴────────┴────────┴────────┴────────┴────────┘
   6位     5位     5位     5位     5位     6位
```

**字段说明**：
- **opcode (6位)**：操作码，唯一标识指令  
- **rs (5位)**：源寄存器1地址（0-31）
- **rt (5位)**：源寄存器2地址（0-31）
- **rd (5位)**：目标寄存器地址（0-31）
- **shamt (5位)**：移位量（0-31），仅移位指令使用
- **保留 (6位)**：预留给功能码或扩展

**适用指令**：ADD, SUB, AND, OR, XOR, SLL, SRL, SRA, CMP, NOP, HALT

**编码示例**：
```assembly
ADD $4, $1, $2
→ opcode=02, rs=1, rt=2, rd=4, shamt=0
→ 000010 00001 00010 00100 00000 000000
→ 0x08220000
```

##### I型指令（Immediate类型）

**格式布局**：
```
 31    26 25   21 20   16 15              0
┌────────┬────────┬────────┬────────────────┐
│ opcode │   rs   │   rt   │      imm       │
└────────┴────────┴────────┴────────────────┘
   6位     5位     5位         16位
```

**字段说明**：
- **opcode (6位)**：操作码
- **rs (5位)**：源寄存器/基址寄存器
- **rt (5位)**：目标寄存器（LOAD/ADDI）或源寄存器（STORE/分支）
- **imm (16位)**：立即数/偏移量/分支目标
  - 算术运算：有符号立即数（-32768到+32767）
  - 访存：地址偏移量
  - 分支：PC相对偏移（字地址，需左移2位）

**适用指令**：ADDI, LOAD, STORE, BZ, BN

**编码示例**：
```assembly
ADDI $1, $0, 100
→ opcode=0D, rs=0, rt=1, imm=100
→ 001101 00000 00001 0000000001100100
→ 0x34010064

LOAD $3, 8($2)
→ opcode=0B, rs=2, rt=3, imm=8
→ 001011 00010 00011 0000000000001000
→ 0x2C430008
```

##### J型指令（Jump类型）

**格式布局**：
```
 31    26 25                           0
┌────────┬─────────────────────────────┐
│ opcode │            addr              │
└────────┴─────────────────────────────┘
   6位              26位
```

**字段说明**：
- **opcode (6位)**：操作码
- **addr (26位)**：跳转目标地址（字地址）
  - 实际地址 = {PC[31:28], addr, 2'b00}
  - 覆盖256MB地址空间

**适用指令**：JMP

**编码示例**：
```assembly
JMP 0x00400010
→ 字地址 = 0x00400010 >> 2 = 0x100004
→ opcode=10, addr=0x100004
→ 010000 00000001000000000000000100
→ 0x40100004
```

#### 2.4.2 各模块功能说明

##### (1) PC (程序计数器)
- **类型**：32位寄存器
- **功能**：保存当前指令地址
- **更新逻辑**：
  - 顺序执行：PC = PC + 4
  - 分支跳转：PC = PC + 4 + (offset << 2)
  - 无条件跳转：PC = {PC[31:28], addr[25:0], 2'b00}
  - 暂停时：PC保持不变

##### (2) IMEM (指令存储器)
- **实现**：Xilinx Distributed Memory Generator IP核
- **容量**：2048字 × 32位 (8KB)
- **接口**：
  - 输入：地址（11位字地址）
  - 输出：32位指令
- **初始化**：通过COE文件加载程序
- **访问**：异步读取（组合逻辑）

##### (3) RegFile (寄存器文件)
- **容量**：32个32位通用寄存器
- **特殊寄存器**：
  - $0 ($zero)：硬件恒为0
  - $29 ($sp)：栈指针（约定）
  - $31 ($ra)：返回地址（约定）
- **端口**：
  - 读端口：2个（rs和rt，同步读取）
  - 写端口：1个（在WB阶段，时钟上升沿写入）
- **特性**：写后读旁路（内部转发）

##### (4) ALU (算术逻辑单元)
- **功能**：执行13种运算
- **输入**：
  - 32位操作数A（来自rs或shamt）
  - 32位操作数B（来自rt或立即数）
  - 4位控制信号aluc
- **输出**：
  - 32位运算结果
  - 标志位：zero, negative, carry, overflow
- **支持运算**：
  - 算术：ADD, SUB
  - 逻辑：AND, OR, XOR
  - 移位：SLL, SRL, SRA

##### (5) DMEM (数据存储器)
- **实现**：Verilog寄存器阵列
- **容量**：32字 × 32位 (128字节)
- **接口**：
  - 地址：5位字地址
  - 数据输入/输出：32位
  - 控制：ena(使能), we(写使能), re(读使能)
- **访问**：同步写，异步读
- **特性**：
  - 写操作在时钟上升沿执行
  - 读操作为组合逻辑（读使能时输出数据，否则高阻态）

##### (6) Hazard_Unit (冒险检测单元)
- **输入**：
  - 各阶段的寄存器地址和控制信号
  - 分支/跳转信号
- **输出**：
  - stall：暂停信号
  - forward_a, forward_b：转发控制(2位)
  - flush_IF_ID, flush_ID_EX：清空信号
- **检测逻辑**：
  - Load-Use冒险
  - 分支数据冒险（ID/EX和EX/MEM阶段）
  - RAW数据冒险（用于转发）

##### (7) 流水线寄存器（4组）

**IF/ID**：
- PC值和指令
- 受flush_IF_ID和stall控制

**ID/EX**：
- 寄存器数据、立即数、寄存器地址
- 控制信号
- 受flush_ID_EX和stall控制

**EX/MEM**：
- ALU结果、rt数据、目标寄存器
- 控制信号
- 不受stall/flush影响（仅复位清零）

**MEM/WB**：
- ALU结果、内存数据、目标寄存器
- 控制信号
- 不受stall/flush影响（仅复位清零）

#### 2.4.3 关键数据通路

##### ① 指令通路
```
PC → IMEM → IF/ID → 指令译码 → 控制信号生成
```

##### ② 数据通路
```
RegFile → ID/EX → [转发MUX] → ALU → EX/MEM → DMEM → MEM/WB → RegFile
                      ↑                  ↓                  ↓
                      └──────────────────┴──────────────────┘
                              数据转发路径
```

##### ③ 控制通路
```
opcode → 控制逻辑 → 控制信号 → 各阶段流水线寄存器 → 功能单元
                           ↓
                    Hazard_Unit → stall/flush/forward
```

#### 2.4.4 时钟与复位

- **时钟频率**：100MHz (10ns周期)
- **复位方式**：异步复位，高电平有效
- **复位效果**：
  - PC复位到0x00400000
  - 所有流水线寄存器清零
  - RegFile保持不变（可预加载数据）
  - halt信号清零

## 🎯 核心特性

### 1. 流水线结构
```
┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐
│   IF   │ → │   ID   │ → │   EX   │ → │  MEM   │ → │   WB   │
│取指令  │   │译码    │   │执行    │   │访存    │   │写回    │
└────────┘   └────────┘   └────────┘   └────────┘   └────────┘
```

### 2. 冒险处理机制

#### 数据冒险
```
指令1: ADD $3, $1, $2    [WB阶段]
指令2: SUB $4, $3, $1    [EX阶段] ← 需要$3，从WB转发
指令3: AND $5, $4, $2    [ID阶段] ← 需要$4，等待
```

**解决方案**：
- EX/MEM → ALU 转发
- MEM/WB → ALU 转发
- Load-Use: 插入气泡（stall）

#### 控制冒险
```
指令1: BN $1, $2, label  [ID阶段] ← 判断是否跳转
指令2: ADD $3, $1, $2    [IF阶段] ← 可能需要清空
指令3: SUB $4, $3, $1    [等待]   ← 可能需要清空
```

**解决方案**：
- 分支跳转时清空IF/ID和ID/EX
- 重定向PC到目标地址

### 3. 指令编码格式

#### R型（寄存器-寄存器）
```
31    26 25   21 20   16 15   11 10    6 5     0
[opcode][  rs  ][  rt  ][  rd  ][shamt ][保留 ]
```

#### I型（立即数）
```
31    26 25   21 20   16 15              0
[opcode][  rs  ][  rt  ][      imm       ]
```

#### J型（跳转）
```
31    26 25                           0
[opcode][           addr               ]
```

## 📈 性能优化建议

### 当前设计
- 简单的分支预测（总是预测不跳转）
- 静态流水线（无动态调度）
- 无Cache（直接访问内存）

### 可能的改进
1. **分支预测**：
   - 1位或2位分支预测器
   - 减少控制冒险损失

2. **动态调度**：
   - 乱序执行
   - 提高ILP（指令级并行）

3. **Cache**：
   - 指令Cache
   - 数据Cache
   - 减少访存延迟

4. **更多指令**：
   - 乘法/除法
   - 浮点运算
   - 向量操作
