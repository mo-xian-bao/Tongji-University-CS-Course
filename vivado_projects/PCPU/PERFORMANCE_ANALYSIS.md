# PCPU 性能分析报告

## 程序基本信息
- **程序名称**：drop_eggs.asm（摔鸡蛋问题）
- **静态指令数**：41条（COE文件行数）
- **算法**：二分查找（Binary Search）
- **测试数据**：100层楼，秘密阈值=37

## 1. 动态指令执行分析

### 1.1 指令分类统计（静态）
根据 `drop_eggs.asm` 代码分析：

| 指令类型                             | 数量   | 占比     |
| ------------------------------------ | ------ | -------- |
| 跳转指令（JMP、BZ、BN）              | 12     | 29.3%    |
| 分支指令（BZ、BN）                   | 7      | 17.1%    |
| 运算指令（ADD、SUB、ADDI、SLL、SRA） | 22     | 53.7%    |
| 其他（HALT）                         | 1      | 2.4%     |
| **总计**                             | **41** | **100%** |

### 1.2 循环次数估算
二分查找算法：
- 搜索范围：0-100（101个数）
- 理论最大迭代次数：⌈log₂(101)⌉ = 7次
- 实际迭代次数（根据threshold=37）：约6-7次

### 1.3 动态指令数计算

假设循环执行了 **N 次**（从波形图可知总周期=158）：

```
动态指令数 = 初始化指令 + (循环体指令 × N) + 结束计算指令

初始化部分（行1-9）：9条
循环体部分（行10-38）：29条（每次循环）
结束计算部分（行39-41）：3条

根据波形周期158，考虑流水线：
实际执行指令数 ≈ 158 - 4（流水线填充） = 154条

因此循环次数 N = (154 - 9 - 3) / 29 ≈ 4.9 ≈ 5次
```

**动态指令数 ≈ 9 + 29×5 + 3 = 157条**（与158周期接近）

## 2. 吞吐率分析（TP - Throughput）

### 2.1 定义
```
TP = 指令条数 / 总时钟周期数
```

### 2.2 计算
```
TP = 157 / 158 = 0.994 ≈ 0.99
```

**结论**：平均每个时钟周期执行约0.99条指令。

接近1的原因：
- 流水线CPU理想情况下每周期可执行1条指令
- 有少量stall（数据冒险、分支判断）导致略低于1

## 3. 加速比分析（S - Speedup）

### 3.1 定义
```
S = 顺序执行所需时钟周期 / 流水线执行所需时钟周期
```

### 3.2 计算各类指令的理想周期

**单周期CPU（假设）**：
- 跳转指令：4个周期
- 分支指令：4个周期  
- 运算指令：4个周期
- HALT：1个周期

**顺序执行总周期**：
根据动态指令分布（需要从仿真波形统计）：
- 假设执行了：
  - 12条跳转（×4） = 48周期
  - 30条分支（×4） = 120周期（分支在循环中多次执行）
  - 110条运算（×4） = 440周期
  - 1条HALT（×1） = 1周期

```
顺序执行总周期 = 48 + 120 + 440 + 1 = 609周期
```

**加速比**：
```
S = 609 / 158 = 3.85
```

**结论**：5级流水线相比单周期CPU获得了约3.85倍的加速。

理论5级流水线加速比应接近5，但由于：
- 数据冒险导致stall
- 控制冒险（分支预测失败）
- 流水线气泡

实际加速比为3.85是合理的。

## 4. 流水线效率分析（E - Efficiency）

### 4.1 定义
```
E = 顺序执行所需的时钟周期 / (总时钟周期数 × 流水线级数)
```

### 4.2 计算
```
E = 609 / (158 × 5) = 609 / 790 = 0.771 = 77.1%
```

**结论**：流水线效率为77.1%，说明：
- 流水线有22.9%的时间处于空闲或stall状态
- 主要损失来自数据冒险和控制冒险

## 5. 指令相关与冲突分析

### 5.1 数据相关（RAW - Read After Write）

**示例1：循环中的数据相关**
```assembly
# 行20-21
add  $t0, $s2, $s3      # $t0 = low + high
addi $t0, $t0, 1        # 读取刚写入的$t0（RAW冒险）
```
**解决**：采用数据转发（Forwarding）从EX/MEM寄存器直接转发到EX阶段。

**示例2：连续计算**
```assembly
# 行33-35
sll  $t1, $s5, 1        # $t1 = m * 2
sll  $t2, $s7, 2        # $t2 = h * 4
add  $t9, $t1, $s6      # 读取$t1（RAW冒险）
```
**解决**：数据转发或插入1个stall周期。

### 5.2 控制相关（分支冒险）

**示例1：条件分支**
```assembly
# 行10-11
bn   $s3, $s2, LOOP_END # 分支判断
bz   $s2, $zero, CHECK_HIGH_ZERO
```
**问题**：分支结果在ID阶段才能确定，导致：
- 分支不跳转：无影响
- 分支跳转：flush IF/ID流水线寄存器，损失1-2个周期

**统计**：
- 程序中有7个分支指令
- 假设50%分支预测失败
- 每次失败损失2周期
- 总损失：7 × 5（循环次数） × 0.5 × 2 ≈ 35周期

这解释了为什么总周期是158而不是理想的157。

### 5.3 结构相关

**本设计中无结构相关**：
- 采用哈佛结构（指令和数据分离）
- 寄存器文件支持双读单写

## 6. CPU运行时间分析

### 6.1 时钟频率
- **系统时钟**：100 MHz（根据约束文件）
- **分频后CPU时钟**：10 Hz（根据Divider_CPU设置）

### 6.2 运行时间

**实际运行时间**（10Hz时钟）：
```
运行时间 = 158周期 / 10 Hz = 15.8秒
```

**理论运行时间**（100MHz时钟）：
```
运行时间 = 158周期 / 100,000,000 Hz = 1.58 μs（微秒）
```

### 6.3 CPI（Cycles Per Instruction）
```
CPI = 总周期数 / 指令数 = 158 / 157 = 1.006
```

**结论**：平均每条指令需要约1个周期，非常接近理想流水线性能。

## 7. 存储器空间使用分析

### 7.1 指令存储器（IMEM）
- **实际使用**：41条指令 × 4字节 = 164字节
- **地址范围**：0x00400000 - 0x004000A4（共41个地址）
- **空间利用率**：根据IMEM大小（假设1KB = 256条指令）= 41/256 = 16%

### 7.2 数据存储器（DMEM）
- **实际使用**：0字节
- **原因**：所有变量都存储在寄存器中，无内存访问（LOAD/STORE）

**优化效果**：
- 无内存访问，消除了内存访问延迟
- 提高了程序执行效率

### 7.3 寄存器使用
使用的寄存器：
- $s0-$s7：8个（保存变量）
- $t0-$t2, $t8-$t9：5个（临时计算）
- $zero：1个（常量0）
- **总计**：14/32 = 43.75%

## 9. 优化建议

1. **减少分支冒险**：
   - 实现静态分支预测（predict not taken）
   - 延迟槽技术

2. **代码优化**：
   - 减少连续数据相关的指令
   - 循环展开

3. **编译器优化**：
   - 指令重排，减少stall
